# اصلاح ثبت و نمایش «منطقه» در آدرس — راهنمای تیم اپلیکیشن

**تاریخ:** 2026-06-14
**مخاطب:** تیم اپلیکیشن موبایل/PWA مشتری
**مرتبط با:** `docs/MOBILE_API_CONTRACT.md` (بخش ۲.۵) و `docs/FRONTEND_LOCATIONS_NESHAN.md`

---

## ۱) مشکل مشاهده‌شده

نمایش فعلی در اپ:

```
استان / شهر:   تهران / تهران
نشانی کامل:    منطقه ۱، تست آدرس منطقه ۱ انتخاب شد
```

این غلط است. نام **منطقه** داخل متن `full_address` چسبانده شده و به‌صورت فیلد ساختاری ذخیره/نمایش نشده.

نمایش درست:

```
استان / شهر / منطقه:   تهران / تهران / منطقه ۱
نشانی کامل:            تست آدرس...        ← فقط جزئیات خیابان، بدون استان/شهر/منطقه
```

---

## ۲) ریشهٔ مشکل (سمت اپ است، نه بک‌اند)

بک‌اند منطقه را **فیلد جداگانه** می‌گیرد (`district_id`) و در پاسخ هم **جداگانه** برمی‌گرداند (`district_name`).
فیلد `full_address` فقط برای متن آزادِ خیابان/کوچه/پلاک/واحد است.

❌ اپ نباید نام استان/شهر/منطقه را داخل `full_address` بنویسد.
✅ اپ باید `city_id` و `district_id` را جدا بفرستد و برای نمایش از فیلدهای ساختاری استفاده کند.

---

## ۳) endpointهای محل (Location)

| Endpoint | توضیح |
|---|---|
| `GET /v1/customer/locations/cities` | شهرهای اصلی؛ هر شهر فیلد `has_districts` دارد |
| `GET /v1/customer/locations/districts?city_id=N` | مناطقِ آن شهر (اجباری بودن `city_id`) |

> فلو: کاربر **شهر** را انتخاب می‌کند، سپس اگر `has_districts=true` بود **منطقه** را. استان از کاربر پرسیده نمی‌شود؛ سرور از روی شهر تشخیص می‌دهد.

**نکتهٔ به‌روز (مهم):** نمایش استان/شهر/منطقه در اپ فقط با وضعیت **«نمایش در اپ» (is_active)** در پنل کنترل می‌شود. گیتِ قدیمیِ جداگانهٔ «محدودهٔ سرویس‌دهی» **حذف شده** است. یعنی هر استان/شهر/منطقه‌ای که در پنل فعال باشد در این endpointها برمی‌گردد و هرچه غیرفعال شود حذف می‌شود.

نمونهٔ پاسخ مناطق:

```jsonc
// GET /v1/customer/locations/districts?city_id=102
{
  "success": true,
  "data": [
    { "id": 110, "city_id": 102, "name": "منطقه ۱ تهران", "slug": "tehran-district-1" }
  ],
  "meta": { "city_id": 102, "total": 22 }
}
```

## ۴) ساخت/ویرایش آدرس — `POST /v1/customer/addresses`

### ✅ درست

```jsonc
{
  "label": "خانه",                 // اختیاری
  "city_id": 102,                  // اجباری — شهر اصلی
  "district_id": 110,              // اختیاری — اگر کاربر منطقه انتخاب کرد، حتماً همین‌جا
  "full_address": "خیابان آزادی، کوچهٔ ۵، پلاک ۱۰، واحد ۳",   // فقط جزئیات خیابان
  "postal_code": "1234567890",     // اختیاری — دقیقاً ۱۰ رقم
  "latitude": 35.7219,             // اختیاری — پین نقشه (با longitude جفت)
  "longitude": 51.3347,
  "phone": "02144556677",          // اختیاری
  "is_default": true
}
```

### ❌ غلط (همین باگ فعلی)

```jsonc
{
  "city_id": 102,
  "full_address": "منطقه ۱، خیابان آزادی، پلاک ۱۰"   // ❌ منطقه داخل متن چسبانده شده
}
```

### قواعد مهم
- `province_id` / `state_id` را **نفرستید** — سرور از روی `city_id` خودش ست می‌کند (ورودی کلاینت نادیده گرفته می‌شود).
- `district_id` باید **فرزندِ همان `city_id`** باشد، وگرنه خطا: «منطقهٔ انتخاب‌شده به این شهر تعلق ندارد.»
- `full_address`: حداقل ۱۰ و حداکثر ۵۰۰ کاراکتر؛ فقط متنِ خیابان (بدون استان/شهر/منطقه).
- سازگاری موقت: اگر اشتباهاً ردیفِ یک «منطقه» را در `city_id` بفرستید، بک‌اند خودکار آن را به `district_id` منتقل و `city_id` را به شهرِ والد اصلاح می‌کند — اما لطفاً از همان اول درست بفرستید.

## ۵) نمایش آدرس (از پاسخ)

پاسخ هر آدرس این فیلدهای ساختاری را دارد:

```jsonc
{
  "id": 7,
  "label": "خانه",
  "full_address": "خیابان آزادی، کوچهٔ ۵، پلاک ۱۰، واحد ۳",
  "state_id": 8,   "state_name": "تهران",
  "city_id": 102,  "city_name": "تهران",
  "district_id": 110, "district_name": "منطقه ۱ تهران",   // اگر منطقه نداشت: null
  "postal_code": "1234567890",
  "phone": "02144556677",
  "latitude": 35.7219, "longitude": 51.3347,
  "is_default": true,
  "created_at": "2026-06-14T10:00:00Z"
}
```

### قالب نمایش پیشنهادی
- **خط اول (سلسله‌مراتب):** `state_name` / `city_name` / `district_name`
  - اگر `district_name === null` بود، آن بخش را حذف کنید → فقط `state_name / city_name`.
- **خط دوم (نشانی):** `full_address`

نتیجه برای مثال بالا:

```
تهران / تهران / منطقه ۱
خیابان آزادی، کوچهٔ ۵، پلاک ۱۰، واحد ۳
```

> خلاصه: نام استان/شهر/منطقه را هیچ‌وقت داخل `full_address` نسازید — همیشه از فیلدهای `*_name` بخوانید و فقط `district_id` را در request بفرستید.

## ۶) ثبت سفارش — یادآوری

سفارش با `address_id` ثبت می‌شود (نه آدرسِ inline). فلو: ابتدا `POST /addresses` → سپس `POST /orders` با `address_id`. بنابراین اگر آدرس درست (با `district_id`) ساخته شود، سفارش هم خودکار منطقهٔ درست را دارد.
