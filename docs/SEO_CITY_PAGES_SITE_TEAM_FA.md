# صفحات سئوی شهری (SEO-024) — نامهٔ تیم سایت (Next.js)

پنل حالا برای هر «شهر اصلی» یک درختِ کاملِ صفحاتِ سئو نگه می‌دارد و از
طریق API در اختیار فرانتِ `tamironline.com` می‌گذارد. رندرِ واقعیِ صفحات و
منطقِ ۴۰۴ **سمتِ شماست**؛ پنل فقط منبعِ داده و وضعیت است.

## درختِ صفحات هر شهر

| نوع (`type`) | مسیر (`path`) | مثال عنوان |
|---|---|---|
| `city` | `/{city}` | تعمیرات لوازم خانگی در مشهد |
| `services` | `/{city}/services` | خدمات تعمیرآنلاین در مشهد |
| `device` | `/{city}/services/{device}` | تعمیر لباسشویی در مشهد |
| `brands` | `/{city}/brands` | برندهای تحت پوشش تعمیرآنلاین در مشهد |
| `brand` | `/{city}/brands/{brand}` | تعمیرات لوازم خانگی بوش در مشهد |
| `combo` | `/{city}/services/{device}/{brand}` | تعمیر لباسشویی بوش در مشهد |

- `{city}`، `{device}`، `{brand}` همان slugهای موجودِ کاتالوگ‌اند
  (مثلاً `mashhad`، `washing-machine`، `bosch`).
- «نمایندگی» عمداً در عنوان‌ها **نمی‌آید** مگر مجوزِ واقعی ثبت شده باشد.

## API

`GET /v1/customer/seo/city-pages` — عمومی، فقط‌خواندنی، کشِ ۱ ساعت.
پاسخ در پوششِ استانداردِ `{ "success": true, "data": [...] }` است.

### حالت فهرست (ساختِ مسیرها/sitemap)
```
GET /v1/customer/seo/city-pages
GET /v1/customer/seo/city-pages?city=mashhad     # فیلترِ یک شهر
```
هر آیتم:
```json
{
  "path": "/mashhad/services/washing-machine/bosch",
  "type": "combo",
  "city":   { "name": "مشهد", "slug": "mashhad" },
  "device": { "name": "لباسشویی", "slug": "washing-machine" },
  "brand":  { "name": "بوش", "slug": "bosch" },
  "title": "تعمیر لباسشویی بوش در مشهد",
  "h1": "…",
  "meta_description": "…",
  "content": "<p>…</p>  یا  null",
  "published_at": "2026-08-29T10:39:28+03:30"
}
```

### حالت واکشیِ یک صفحه
```
GET /v1/customer/seo/city-pages?path=/mashhad/services/washing-machine/bosch
```
- اگر صفحه **منتشرشده** باشد → `200` با `data` همان آیتمِ بالا.
- اگر منتشر نشده یا اصلاً وجود نداشته باشد → **`404`**.

## قواعدِ حیاتی برای سمتِ سایت (SEO-001)

1. **فقط `path`هایی که این API برمی‌گرداند باید روی سایت وجود داشته باشند.**
   هر مسیرِ دیگری زیرِ این الگوها (شهر/دستگاه/برندِ نامعتبر، یا صفحهٔ
   منتشرنشده) باید **۴۰۴ واقعی** بدهد (status 404 + `notFound()` در
   Next.js) — نه ریدایرکت، نه صفحهٔ خالی.
2. صفحاتِ **پیش‌نویس** هرگز از API نمی‌آیند؛ تا مدیر در پنل منتشرشان نکند
   نباید روی سایت، منو، لینک‌های داخلی یا sitemap ظاهر شوند.
3. `content` ممکن است `null` باشد؛ در آن صورت از قالبِ پیش‌فرضِ خودِ سایت
   برای آن نوع صفحه استفاده کنید (title/h1/meta از API می‌آید).

## Sitemap

پنل صفحاتِ **منتشرشده** را در sitemap منتشر می‌کند:
- فایلِ جدید `sitemap-local.xml` در `sitemap.xml` معرفی شده.
- فقط `status=published` می‌آید؛ پیش‌نویس/بایگانی خودکار حذف می‌شوند.
- اگر سایت sitemapِ خودش را می‌سازد، از حالتِ فهرستِ API استفاده کنید و
  فقط `path`های برگشتی را قرار دهید.

## چرخهٔ عمر (برای هماهنگی)

- ساختِ شهرِ اصلی در پنل → صفحات به‌صورت **پیش‌نویس** ساخته می‌شوند.
- افزودن تدریجیِ تکنسین/دستگاه/برند → مدیر «همگام‌سازی» می‌زند و صفحاتِ
  تازه (باز هم پیش‌نویس) اضافه می‌شوند.
- مدیر در پنل بررسی و **منتشر** می‌کند → همان لحظه در API و sitemap ظاهر
  می‌شوند و سایت باید رندرشان کند.
- «باطل/بازگردانی به پیش‌نویس» → از API خارج می‌شوند و سایت باید ۴۰۴ بدهد.

> توسعهٔ آینده (فعلاً پیاده نشده): بردنِ شهرهای یک استان زیرِ صفحهٔ استان
> (`/{province}/…`). فیلدِ `province_id` از همین حالا در دادهٔ صفحات هست تا
> این توسعه بدونِ تغییرِ ساختار ممکن باشد.
