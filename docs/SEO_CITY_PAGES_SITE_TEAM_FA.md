# نامهٔ نهایی به تیم توسعهٔ سایت (Next.js) — صفحات سئوی شهری (SEO-024)

این سند مرجعِ کاملِ پیاده‌سازیِ صفحاتِ شهری روی `tamironline.com` است.
پنل منبعِ داده و وضعیت است؛ **رندر، ۴۰۴ و منو سمتِ شماست.**

---

## ۰) دو اصلِ طلایی

1. **هر صفحه مستقل است.** لازم نیست صفحاتِ والد لایو باشند. اگر فقط
   `/mashhad/services/washing-machine` را منتشر کنید، باید **بدونِ هیچ
   مشکلی** کار کند — بردکرامب، متا و اسکیمایش کامل است، حتی اگر `/mashhad`
   یا `/mashhad/services` هنوز منتشر نشده باشند.
2. **فقط صفحاتِ «منتشرشده» وجود دارند.** هر مسیرِ دیگر زیرِ این الگوها باید
   **۴۰۴ واقعی** بدهد (`notFound()` در Next.js) — نه ریدایرکت، نه صفحهٔ خالی.

---

## ۰.۵) پاسخ به گزارشِ فرانت — پیشوندِ `/city/` (هماهنگ شد ✅)

تصمیمِ کارفرما «`/city/`» تأیید است و بک‌اند هماهنگ شد:

- **`sitemap-local.xml`** حالا تک‌تکِ URLها را با پیشوندِ `/city/` می‌دهد
  (`{site}/city/mashhad/...`). ✅ (موردِ حیاتی)
- **`breadcrumbs[].path`** حالا `/city/`-دار برمی‌گردد (خانه `/` بدونِ پیشوند). ✅
- **canonical** در `GET /v1/seo/meta?type=city_page` حالا `/city/...` است
  (الگوی url به `/city{path}` تغییر کرد؛ double-slashِ قبلی هم رفع شد). ✅
- **کوئریِ `?path=` و `?slug=` ریشه‌ای می‌مانند** (بدونِ `/city`) و صفحات با
  همان کلیدِ ریشه‌ای (`/mashhad/...`) key می‌شوند — همان‌طور که فرانت می‌فرستد.
  تأیید شد؛ نیازی به تغییر در `toApiPath` نیست. ✅
- **کلیدهای `sections_enabled`** پنل دقیقاً به فهرستِ فرانت هم‌نام شد
  (بخش ۳.۶). ✅

> پس فقط `data.path` و کوئری‌ها ریشه‌ای‌اند؛ هر چیزِ «آدرسِ عمومی» (sitemap،
> breadcrumb، canonical) از سمتِ بک‌اند `/city/`-دار است.

## ۱) درختِ صفحات و مسیرها

| نوع (`type`) | مسیر (`path`) | نمونه عنوان |
|---|---|---|
| `city` | `/{city}` | تعمیرات لوازم خانگی در مشهد |
| `services` | `/{city}/services` | خدمات تعمیرآنلاین در مشهد |
| `device` | `/{city}/services/{device}` | تعمیر لباسشویی در مشهد |
| `brands` | `/{city}/brands` | برندهای تحت پوشش در مشهد |
| `brand` | `/{city}/brands/{brand}` | تعمیرات لوازم خانگی بوش در مشهد |
| `combo` | `/{city}/services/{device}/{brand}` | تعمیر لباسشویی بوش در مشهد |

`{city}`/`{device}`/`{brand}` همان slugهای کاتالوگ‌اند (`mashhad`،
`washing-machine`، `bosch`). واژهٔ «نمایندگی» عمداً در عنوان‌ها نمی‌آید مگر
مجوزِ واقعی ثبت شده باشد.

## ۲) API محتوا

`GET /v1/customer/seo/city-pages` — عمومی، فقط‌خواندنی، کشِ ۱ ساعت.
پاسخ در پوششِ `{ "success": true, "data": … }` است.

### حالت فهرست (ساختِ مسیرها / `generateStaticParams` / sitemap)
```
GET /v1/customer/seo/city-pages            # همهٔ صفحاتِ منتشرشده
GET /v1/customer/seo/city-pages?city=mashhad   # فقط یک شهر
```

### حالت واکشیِ یک صفحه (رندرِ صفحه)
```
GET /v1/customer/seo/city-pages?path=/mashhad/services/washing-machine/bosch
```
- منتشرشده → `200` با آبجکتِ زیر.
- منتشرنشده یا ناموجود → **`404`** (همین را به `notFound()` وصل کنید).

### شکلِ هر آیتم
```json
{
  "path": "/mashhad/services/washing-machine/bosch",
  "type": "combo",
  "city":   { "name": "مشهد", "slug": "mashhad" },
  "device": { "name": "لباسشویی", "slug": "washing-machine" },
  "brand":  { "name": "بوش", "slug": "bosch" },

  "title": "…", "h1": "…",
  "eyebrow": "…|null", "subtitle": "…|null", "caption": "…|null",
  "content": "<p>…</p>|null",

  "hero_image": { "mobile": { "url": "…", "alt": "…" } } | null,
  "cta_primary":   { "label", "url", "icon" } | null,
  "cta_secondary": { "label", "url", "icon" } | null,
  "steps_image": { "desktop": "…|null", "mobile": "…|null" },
  "sections_enabled": { "hero": true, "faq": false, … } | null,

  "breadcrumbs": [
    { "label": "خانه",     "path": "/",                                  "current": false },
    { "label": "مشهد",     "path": "/mashhad",                           "current": false },
    { "label": "خدمات",    "path": "/mashhad/services",                  "current": false },
    { "label": "لباسشویی", "path": "/mashhad/services/washing-machine",  "current": false },
    { "label": "لباسشویی بوش", "path": "/mashhad/services/washing-machine/bosch", "current": true }
  ],

  "meta_title": "…|null", "meta_description": "…|null",
  "published_at": "2026-08-29T10:39:28+03:30"
}
```

### ⚠️ بدنهٔ صفحه = `content`ِ صفحهٔ شهری (مهم — باگِ فعلی)

**مشکلِ گزارش‌شده:** ادمین در پنل برای صفحهٔ `/karaj/services/washing-machine`
محتوا می‌نویسد، ولی سایت محتوایِ صفحهٔ عمومیِ «لباسشویی» (از کاتالوگ) را نشان
می‌دهد — یعنی `content`ِ صفحهٔ شهری نادیده گرفته می‌شود.

**قاعدهٔ درست (لطفاً اعمال کنید):**
1. اگر `content`ِ صفحهٔ شهری **غیرخالی** بود → **همان** بدنهٔ صفحه است
   (جایگزینِ محتوای کاتالوگِ دستگاه/برند می‌شود). این متن در پنل نوشته و در
   payload با توکن‌های resolve‌شده برمی‌گردد.
2. فقط اگر `content`ِ شهری **خالی/`null`** بود → به محتوای کاتالوگِ همان
   دستگاه/برند fallback کنید (رفتارِ فعلی).

به‌طورِ کلی برای صفحهٔ شهری، **همیشه اولویت با فیلدهای payloadِ city است**
(title/h1/subtitle/caption/content/hero/…)؛ کاتالوگ فقط fallback و منبعِ
سکشن‌های مشترک (FAQ/نظرات) است.

### نکتهٔ تصویرِ Hero (یک تصویر + وراثت از والد)
`hero_image` حالا **یک تصویر** است (کلیدِ `mobile`). همان یک تصویر را در
دسکتاپ و موبایل استفاده کنید.

**وراثت خودکار:** این مقدار در API **از قبل resolve شده** است — اگر عکسِ
خودِ صفحه خالی باشد، پنل خودش عکسِ والد را می‌گذارد؛ پس شما همیشه فقط
`hero_image` را بخوانید و نگرانِ fallback نباشید:
- `تعمیر لباسشویی بوش در کرج` (combo) → عکسِ خودش ← عکسِ **دستگاه** (لباسشویی)
- `تعمیر لباسشویی در کرج` (device) → عکسِ خودش ← عکسِ **دستگاه**
- `تعمیرات … بوش در کرج` (brand) → عکسِ خودش ← عکسِ **برند**
- اگر باز هم `null` بود → از تصویرِ پیش‌فرضِ خودتان.

(دقیقاً همان الگوی صفحاتِ ترکیبیِ فعلی: `لباسشویی بوش → لباسشویی`.)

### نکتهٔ سکشن‌ها
`sections_enabled = null` یعنی «همه روشن». محتوای FAQ/نظرات در payloadِ صفحه
تکرار نمی‌شود؛ از همان endpointهای موجودِ FAQ/نظرات بخوانید (سکشن‌هایی که
`false` هستند را نسازید).

## ۳) بردکرامب — خودکار و مستقل

آرایهٔ `breadcrumbs` را پنل از روی **دادهٔ خودِ صفحه** می‌سازد و به وجودِ
صفحاتِ والد وابسته نیست. پس:
- مستقیماً همین آرایه را رِندر کنید (کوچک‌ترین منطق سمتِ شما).
- برای `BreadcrumbList` در JSON-LD هم از همین `path`/`label`ها استفاده کنید.
- آیتمِ `current:true` صفحهٔ فعلی است (بدونِ لینک نمایش دهید).
- اگر یک صفحهٔ میانی منتشر نشده، لینکش ممکن است ۴۰۴ بدهد؛ در آن حالت
  می‌توانید آن آیتم را به‌صورتِ متنِ ساده (بدون لینک) نشان دهید. توصیه:
  چون پنل کلِ درخت را می‌سازد، معمولاً صفحاتِ والد را هم منتشر کنید.

---

## ۳.۵) الگوی متغیرهای عنوان — افزودنِ {شهر}

صفحاتِ شهری همان الگوی متغیرِ صفحاتِ فعلی‌اند، فقط متغیرِ **`{city}`** به
انتها اضافه می‌شود:

| صفحه | الگوی متغیر | نمونه |
|---|---|---|
| ترکیبیِ فعلی (بدونِ شهر) | `تعمیر {device} {brand}` | تعمیر لباسشویی بوش |
| ترکیبیِ شهری | `تعمیر {device} {brand} در {city}` | تعمیر لباسشویی بوش در کرج |
| دستگاهِ شهری | `تعمیر {device} در {city}` | تعمیر لباسشویی در کرج |
| برندِ شهری | `تعمیرات لوازم خانگی {brand} در {city}` | … بوش در کرج |

- عنوان/H1/متایِ هر صفحه از قبل با همین الگو در پنل ساخته می‌شود (و مدیر
  می‌تواند override کند). شما فقط `title`/`h1` را از payload بخوانید.
- در پنلِ سئوی حرفه‌ای، متغیرهای `%device%` / `%brand%` / `%city%` برای
  صفحاتِ شهری از خودِ رکورد پر می‌شوند (`%city%` = شهرِ همان صفحه).

## ۳.۶) کلیدهای `sections_enabled` (هم‌نام با فرانت)

پنل از همین نام‌ها استفاده می‌کند؛ هر کلیدِ غایب = روشن، فقط `false` مخفی می‌کند:
`hero`, `activity`, `steps`, `content`, `pricing`, `faq`, `brands`,
`otherDevices`, `videos`, `forum`, `related`, `testimonials`, `promo`, `links`.

## ۳.۷) متغیرهای پویا در متن (FAQ / محتوا) — نیازمندِ اقدامِ فرانت

ادمین می‌تواند در متنِ صفحات این توکن‌ها را بنویسد و با مقدارِ واقعیِ همان
صفحه پر می‌شوند:

| توکن | مقدار |
|---|---|
| `{city}` | نامِ شهر (مثلاً مشهد) |
| `{device}` | نامِ دستگاه |
| `{brand}` | نامِ برند |
| `{province}` | نامِ استان |

- **فیلدهای خودِ صفحه** (title/h1/eyebrow/subtitle/caption/content/meta) را
  **بک‌اند از قبل resolve می‌کند** — شما همان متنِ آماده را نمایش دهید.
- **اما محتوایی که از کاتالوگ می‌آید** (بدنهٔ FAQ، سوال/جواب، نظرات، متنِ
  مشترکِ دستگاه/برند) **در بک‌اندِ کاتالوگ resolve نمی‌شود** — چون آن محتوا
  مشترک و غیرشهری است. پس **فرانت باید همین توکن‌ها را هنگامِ رندرِ صفحهٔ
  شهری با contextِ شهر جایگزین کند** (شما `city`/`device`/`brand` را از
  payloadِ صفحه دارید؛ `province` را هم می‌توانید از همان‌جا بگیرید اگر
  اضافه شود، یا فعلاً همان سه‌تا).
- مثال: یک FAQ با متنِ «آیا در {city} خدمات دارید؟» روی صفحهٔ مشهد باید
  «آیا در مشهد خدمات دارید؟» رِندر شود.

> قاعدهٔ توکن یکسان است (`{city}`، `{device}`، `{brand}`، `{province}`) تا
> در پنل و فرانت یک‌جور کار کند.

## ۴) متای سئوی حرفه‌ای (canonical / robots / OG / Schema)

مدیریتِ سئو در پنل **یکپارچه** است (یک پنلِ واحد برای همهٔ انواع صفحه —
دستگاه/برند/شهر). متایِ رزولوشن‌شده را از **همان endpointِ عمومیِ متا** که
برای بقیهٔ صفحات استفاده می‌کنید بگیرید:

```
GET /v1/seo/meta?type=city_page&slug={path}
```
- `type` همیشه ثابتِ `city_page` است (نه نوعِ صفحه).
- `{path}` دقیقاً همان `path` (با اسلشِ ابتدایی).
- خروجی: `title, description, canonical, robots, og, twitter, jsonld` —
  دقیقاً مثلِ بقیهٔ انواع. اگر صفحه `noindex` خورده باشد در `robots` می‌آید و
  از sitemap هم حذف است.

فیلدهای سادهٔ `title`/`meta_description` داخلِ payloadِ محتوا صرفاً fallbackِ
سریع‌اند؛ **مرجعِ نهاییِ متا، خروجیِ `/v1/seo/meta` است.**

## ۵) Sitemap

- صفحاتِ **منتشرشده** در `sitemap-local.xml` می‌آیند و در `sitemap.xml`
  معرفی شده‌اند. **URLها `/city/`-دارند** (مثلِ `{site}/city/mashhad/...`).
- پیش‌نویس/بایگانی و صفحاتِ `noindex` خودکار حذف می‌شوند.
- اگر خودتان هم sitemap می‌سازید، `path`های ریشه‌ایِ API را با پیشوندِ
  `/city` بدهید.

---

## ۶) چرخهٔ عمر (برای هماهنگی)

> **تولید خودکار:** صفحاتِ شهری دقیقاً مثلِ صفحاتِ ترکیبیِ فعلی (device×brand)
> **خودکار** ساخته می‌شوند — بر اساسِ پوششِ واقعیِ تکنسین‌ها، فقط برای
> ترکیب‌های معتبر. شما چیزی نمی‌سازید؛ فقط منتشرشده‌ها را می‌خوانید.

1. ساختِ شهرِ اصلی در پنل → کلِ درخت به‌صورت **پیش‌نویس** ساخته می‌شود.
2. مدیر بررسی و **منتشر** می‌کند → همان لحظه در API و sitemap ظاهر می‌شوند.
3. «بازگردانی به پیش‌نویس»/«بایگانی» → از API خارج و روی سایت باید ۴۰۴ شوند.

> توسعهٔ آینده: بردنِ شهرها زیرِ صفحهٔ استان (`/{province}/…`). فیلدِ
> `province_id` از حالا در داده هست تا این کار بدونِ تغییرِ ساختار ممکن باشد.
