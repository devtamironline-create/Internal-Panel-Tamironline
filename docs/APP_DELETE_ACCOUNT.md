# اپ — حذفِ حساب توسطِ کاربر (delete-account)

الزامِ استورها (گوگل/اپل) و درخواستِ مدیریت: کاربر باید بتواند حسابش را از
داخلِ اپ حذف کند. بک‌اند آماده است — حذف **نرم (soft delete)** است: اطلاعات و
سفارش‌ها حفظ می‌شوند، ادمین در پنل حساب را می‌بیند و می‌تواند بازگرداند.

## Endpoint — `POST /v1/customer/delete-account`

- **Auth الزامی** (همان Bearer tokenِ sanctum؛ داخلِ گروهِ private اپ).
- Body (اختیاری):

```jsonc
{ "reason": "دیگر نیازی ندارم" }   // اختیاری، تا ۵۰۰ کاراکتر — به ادمین نمایش داده می‌شود
```

- پاسخِ موفق (200):

```jsonc
{
  "message": "حساب شما حذف شد. اگر منصرف شدید، پشتیبانی می‌تواند حساب را بازگرداند.",
  "data": { "deleted": true }
}
```

## بعد از حذف چه می‌شود؟

- **همه‌ی توکن‌های کاربر (همه‌ی دستگاه‌ها) باطل می‌شوند** — هر درخواستِ بعدی 401.
- اپ باید بعد از 200: توکن/استوریجِ محلی را پاک کند و به صفحه‌ی ورود برگردد.
- ورودِ دوباره با همان شماره تا بازگردانی ممکن نیست — `POST /v1/auth/verify-otp`
  خطای اعتبارسنجی برمی‌گرداند:
  «این حساب به درخواستِ شما حذف شده است. برای بازگردانی با پشتیبانی تماس بگیرید.»
  → اپ همین پیام را نمایش دهد (خطای فیلدِ `mobile`، ساختارِ خطای استاندارد).

## UX پیشنهادی

1. صفحه‌ی «حذف حساب» در تنظیمات/پروفایل با توضیحِ عواقب (خروج از همه‌ی
   دستگاه‌ها، عدمِ امکانِ ورود تا تماس با پشتیبانی).
2. تأییدِ دومرحله‌ای (مثلاً تایپِ «حذف» یا دکمه‌ی hold) + فیلدِ اختیاریِ «دلیل».
3. بعد از موفقیت: پیامِ خداحافظی + پاکسازیِ session و هدایت به onboarding.

## سمتِ پنل (اطلاع برای تیم)

- «CRM ← مشتری‌ها» فیلترِ جدیدِ **«حساب‌های حذف‌شده»** (با شمارنده) دارد.
- صفحه‌ی جزئیاتِ مشتریِ حذف‌شده: بنرِ قرمز با تاریخِ حذف + دلیلِ اعلام‌شده‌ی
  کاربر + دکمه‌ی **«بازگردانیِ حساب»**. بعد از بازگردانی، ورودِ کاربر با همان
  شماره و همان تاریخچه (سفارش‌ها/فاکتورها) برقرار می‌شود.
