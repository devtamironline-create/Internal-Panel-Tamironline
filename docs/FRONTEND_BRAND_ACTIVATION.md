# نامهٔ فرانت — فعال/غیرفعال‌سازی برندها (و دستگاه‌ها) در سایت

سلام تیم فرانت 👋

از این پس مدیرِ پنل می‌تواند هر **برند** (و **دستگاه**) را در سایت **فعال یا غیرفعال** کند.
این کنترل کاملاً سمتِ بک‌اند اعمال می‌شود؛ شما فقط باید رفتارِ «نبودن/۴۰۴» را درست هندل کنید.

> این یک تغییرِ **غیرشکستنده** است. APIها همان شکلِ قبلی را دارند؛ فقط آیتم‌های
> غیرفعال دیگر برنمی‌گردند.

---

## رفتارِ بک‌اند (منبعِ حقیقت)

- **لیستِ برندها** — `GET /v1/catalog/brands`
  فقط برندهای **فعال** را برمی‌گرداند. `meta.total` هم فقط فعال‌ها را می‌شمارد.
- **جزئیاتِ برند** — `GET /v1/catalog/brands/{slug}`
  اگر برند غیرفعال (یا حذف) باشد → **`404`**.
- **صفحهٔ ترکیبیِ دستگاه×برند** — `GET /v1/catalog/devices/{deviceSlug}/{brandSlug}`
  اگر **برند یا دستگاه** غیرفعال باشد → **`404`**.
- **لیستِ برندهای داخلِ صفحهٔ دستگاه** — برندهای غیرفعال در آن لیست نمی‌آیند.
- **دستگاه‌ها** دقیقاً همین رفتار را دارند: `GET /v1/catalog/devices`
  فقط فعال‌ها، و `GET /v1/catalog/devices/{slug}` غیرفعال → `404`.
- **سئو:** صفحهٔ برند/دستگاهِ غیرفعال خودکار `noindex` می‌شود، از `sitemap` حذف
  می‌گردد، و در `‎/v1/seo/meta?type=brand_device&slug=…` پرچمِ `robots` آن
  `noindex` خواهد بود.

---

## کارهایی که فرانت باید انجام دهد ✅

1. **هندلِ ۴۰۴ در صفحاتِ جزئیات.** اگر `‎/catalog/brands/{slug}` یا
   `‎/catalog/devices/{device}/{brand}` کدِ `404` داد، با `notFound()` صفحهٔ
   ۴۰۴ را نشان دهید (لینکِ یک برندِ غیرفعال نباید ارورِ رندر بدهد):
   ```ts
   const res = await fetch(`${BACKEND}/v1/catalog/brands/${slug}`, { next: { revalidate: 600 } });
   if (res.status === 404) notFound();
   ```

2. **لیست‌ها را همیشه از API بگیرید.** هیچ فهرستِ برند/دستگاهی را hard-code یا
   به‌صورتِ دائمی cache نکنید. لیستِ برندها/دستگاه‌ها ممکن است هر زمان تغییر کند.

3. **`generateStaticParams` را از همین APIهای لیست بسازید** (نه از یک فایلِ ثابت)،
   تا برندِ غیرفعال اصلاً به مسیرهای استاتیک نرود:
   ```ts
   export async function generateStaticParams() {
     const r = await fetch(`${BACKEND}/v1/catalog/brands?limit=100`).then(r => r.json());
     return r.data.map((b: { slug: string }) => ({ brand: b.slug }));
   }
   ```

4. **ISR / revalidate.** چون این APIها `Cache-Control` کوتاه (~۱۰ دقیقه) دارند،
   از `next: { revalidate: 600 }` استفاده کنید تا غیرفعال‌شدنِ یک برند ظرفِ
   چند دقیقه روی سایت اعمال شود (نیازی به دیپلویِ مجدد نیست).

5. **لینک‌سازیِ داخلی.** چون لیست‌ها فقط فعال‌ها را می‌دهند، اگر صرفاً از همان
   داده‌ها لینک بسازید، خودبه‌خود به برندِ غیرفعال لینک نمی‌دهید. فقط مراقبِ
   لینک‌های دستی/قدیمی باشید (آن‌ها با هندلِ ۴۰۴ امن می‌شوند).

## شکلِ پاسخ‌ها (بدون تغییر)

```jsonc
// GET /v1/catalog/brands  → فقط فعال‌ها
{ "data": [ { "id": 5, "name": "ال جی", "slug": "lg", "logo": null } ],
  "meta": { "total": 42 } }

// GET /v1/catalog/brands/lg  → 200 اگر فعال، 404 اگر غیرفعال
```

> نکته: slugها به‌زودی همگی **انگلیسی** می‌شوند (مثلاً `lg`, `bosch`, `samsung`).
> برای جزئیاتِ آن، سندِ slug جداگانه را ببینید.

---

## خلاصه برای QA

- یک برند را در پنل غیرفعال کنید → باید ظرفِ ~۱۰ دقیقه (یا با revalidate) از
  لیستِ برندهای سایت حذف شود و صفحه‌اش `404` بدهد.
- صفحهٔ ترکیبیِ آن برند با هر دستگاهی هم `404` شود.
- در Search Console، آن URLها باید `noindex`/خارج از sitemap دیده شوند.
