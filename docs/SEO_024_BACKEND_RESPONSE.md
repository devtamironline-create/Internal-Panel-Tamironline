# نامه به تیم فرانت سایت — پاسخِ بک‌اند به SEO-024

**موضوع:** موارد لازم از بک‌اند (بخش ۲ نامهٔ شما) — همه انجام شد ✅

سلام. کلِ موارد لازمِ سمتِ بک‌اند برای «نشکستنِ سئو» پیاده و روی `main` مرج شد.
نکته‌به‌نکتهٔ نامهٔ شما:

---

## ۲.۱ پیشوندِ `/city/` — از قبل درست بود ✅
- **`sitemap-local.xml`**: تک‌تکِ URLها با پیشوندِ `/city/` تولید می‌شوند
  (`/city/{path}`).
- **`breadcrumbs[].path`**: همگی `/city/`-دار برمی‌گردند (به‌جز «خانه» که `/`
  می‌ماند). لازم نیست خودتان پیشوند بزنید.

## ۲.۲ کوئریِ `?path=` و `slug` متا — تأیید شد ✅
صفحات با کلیدِ **ریشه‌ای** (بدونِ `/city`) key می‌شوند؛ دقیقاً همان‌طور که
می‌فرستید:
- `GET /v1/customer/seo/city-pages?path=/mashhad/services/washing-machine`
- `GET /v1/seo/meta?type=city_page&slug=/mashhad/services/washing-machine`

## ۲.۳ کلیدهای `sections_enabled` — بدون تغییر ✅
عیناً پاس داده می‌شوند؛ `false` = مخفی، غایب/`null` = روشن.

## ۲.۳.۵ توکنِ `{province}` — انجام شد ✅
- توکن‌های فیلدهای خودِ صفحه (h1/subtitle/content/…) را بک‌اند resolve می‌کند.
- آبجکتِ `province` هم در payload هست تا `{province}` را در محتوای کاتالوگ resolve
  کنید:
```json
"province": { "name": "خراسان رضوی", "slug": "khorasan-razavi" }   // یا null
```

## ۲.۳.۶ سکشن‌های سطحِ شهر برای صفحاتِ فهرستی — انجام شد ✅
روی صفحاتِ **هاب** (`city` / `services` / `brands`) این چهار سکشن اضافه شد،
**در همان شکلِ سکشن‌های صفحاتِ دستگاه** تا با همان کامپوننت‌ها وصل کنید. روی
`device`/`brand`/`combo` این‌ها `null`اند (شما از کاتالوگ می‌خوانید).

### شهر/استان چطور دخیل است؟
- **`faq`**: از FAQهایی که **ادمین per-city** به همان صفحهٔ شهری وصل می‌کند —
  یعنی ذاتاً مخصوصِ همان شهر است. توکن‌های `{city}`/`{province}`/`{device}`/`{brand}`
  در متنِ سؤال/پاسخ **resolve** می‌شوند.
- **`videos` و `forum_questions`**: آیتم‌ها یک **مجموعهٔ عمومی** هستند (چون
  ویدیو/سؤالِ انجمن در دیتابیس به شهر گره نمی‌خورند)، **اما عنوانِ سکشن با نامِ
  شهر و استان بومی‌سازی می‌شود** تا صفحه از نظرِ سئو به همان شهر/استان مرتبط بماند
  (مثلاً: «پرسش‌های متداولِ تعمیرات در مشهد، خراسان رضوی»).
- **`related_articles`**: طبقِ خواستِ کارفرما **«آخرین مقالات»** (عمومی) — بدونِ
  بومی‌سازیِ عنوان.

> اگر بعداً بخواهید `videos`/`forum_questions`/`related_articles` هم per-city
> توسطِ ادمین انتخاب شوند (مثلِ FAQ)، همان الگو در چند دقیقه اضافه می‌شود.

### شکلِ دقیقِ payload (فقط صفحاتِ هاب)

```json
"faq": [ { "q": "…", "a": "…" } ],            // یا null

"videos": {
  "title": "ویدیوهای آموزشیِ تعمیرات در مشهد، خراسان رضوی",
  "subtitle": null,
  "items": [ {
    "title": "…", "aparat_id": null, "youtube_id": null,
    "video_url": "…", "description": "…", "poster_url": "…",

},

"forum_questions": {
  "title": "پرسش‌های متداولِ تعمیرات در مشهد، خراسان رضوی",
  "subtitle": null,
  "see_all_label": null,

    "id": 12, "slug": "…", "title": "…", "url": "/forum/12-…",
```

نکته: عنوانِ `videos`/`forum_questions` وقتی شهر موجود باشد پسوندِ « در {شهر}، {استان}»
می‌گیرد؛ اگر استان نبود فقط « در {شهر}»، و اگر هیچ‌کدام نبود عنوانِ ساده. همهٔ
آیتم‌ها best-effort هستند؛ اگر منبعی خطا بدهد آرایهٔ خالی می‌آید و صفحه نمی‌شکند.

## ۲.۴ / ۲.۵ — بدون تغییر ✅
بدنهٔ `device`/`brand`/`combo` را مثل قبل از `/v1/catalog/...` بخوانید؛ فقط
H1/زیرعنوان/تصویر/بردکرامب/متا/سکشن‌ها از payloadِ city می‌آید. منو/لینک‌ها فقط از
صفحاتِ **منتشرشده** می‌آیند.

## ۲.۶ وضعیتِ endpoint
`GET /v1/customer/seo/city-pages` لایو است. بعد از دیپلوی یک مسیرِ نمونه
(مثلاً مشهد) را منتشر می‌کنیم تا انتها‌به‌انتها (رندر + sitemap + توکن‌ها) را با
هم تست کنیم.

حاضرند — با FAQِ per-city و عنوان‌های بومی‌شده به شهر/استان، و مقالاتِ «آخرین».
