# پاسخ به نامه‌ی فرانت — «فعالیت زنده» واقع‌گرایانه شد

> اندپوینت: `GET /v1/.../activity` (روی BFF: `/api/activity`) | وضعیت: ✅ انجام شد

## چه چیزی اصلاح شد

### ۱) دیگر ترکیبِ ناممکن ساخته نمی‌شود ✅
قبلاً برند به‌صورت **کاملاً تصادفی** به دستگاه نسبت داده می‌شد → «آبسال + ماشین لباسشویی». حالا:

- برند فقط وقتی به یک دستگاه نسبت داده می‌شود که **صفحه‌ی ترکیبیِ فعال** (`DeviceBrandPage.is_active = true`) برای آن جفت وجود داشته باشد — همان منبعِ «مدیریت صفحات ترکیبی / combo-manager».
- اگر دستگاهی هیچ ترکیبِ فعالی نداشته باشد → **بدون برند** ارسال می‌شود (فقط «تعمیر ماشین لباسشویی») که همیشه درست است.
- برای تنوعِ طبیعی، حتی وقتی برندِ سازگار هست، با ۳۰٪ احتمال آیتم بدون برند می‌آید.

### ۲) صفحه‌ی برند (`?brand_slug`) ✅
دستگاه‌ها به آن‌هایی محدود می‌شوند که با این برند **ترکیبِ فعال** دارند. پس مثلاً صفحه‌ی «آبسال» هیچ‌وقت «ماشین لباسشویی آبسال» نشان نمی‌دهد مگر این ترکیب در پنل فعال باشد.

### ۳) تنوع و واقع‌گرایی ✅
- `area`: از فهرست واقعیِ محله‌های تهران/کرج (config موجود) — و دیگر **پشت‌سرهم تکرار نمی‌شود**.
- `device`: دستگاهِ هر آیتم با آیتمِ قبلی فرق دارد (بدونِ تکرارِ متوالی).
- `minutes_ago`: توزیعِ واقع‌نمایانه (بیشتر در ۳۰ دقیقه‌ی اخیر، صعودی).

### ۴) مشکلِ واقعیِ دستگاه در متن (`problem`) ✅ — جدید
هر دستگاه در پنل یک فهرستِ **«مشکلات رایج»** دارد (صفحهٔ ویرایش دستگاه → بخشِ
«مشکلات رایج دستگاه»). حالا هر آیتمِ فعالیت، در صورتِ وجود، یک مشکلِ **واقعیِ
همان دستگاه** را هم نشان می‌دهد:

- `device_label` به‌شکلِ «تعمیر [دستگاه] [برند] – [مشکل]» می‌آید، مثلِ
  «تعمیر لباسشویی سامسونگ – آبگیری نمی‌کند».
- فیلدِ جداگانهٔ `problem` هم اضافه شد (اگر بخواهید جدا نمایش دهید).
- اگر دستگاهی هیچ مشکلی در پنل تعریف‌نشده باشد → `problem: null` و متن فقط
  «تعمیر [دستگاه] [برند]» می‌ماند. **هیچ‌وقت مشکلِ ساختگی ساخته نمی‌شود.**
- مشکل‌ها هم پشت‌سرهم تکرار نمی‌شوند (مثلِ device/area).

### ۵) شمارِ واقعیِ «امروز» (`today_count`) ✅
عددِ واقعیِ **سفارش‌های انجام‌شده‌ی امروز** (`status = completed`، `completed_at >= شروعِ امروز`، timezone = Asia/Tehran). دیگر لازم نیست فرانت فرمولِ محلیِ `items*30+47` بسازد.

## شکلِ نهاییِ پاسخ (مهم — کمی با پیشنهادِ نامه فرق دارد)

برای **حفظِ سازگاریِ کامل با فرانتِ فعلی**، `data` همان آرایه‌ی آیتم‌ها ماند و `today_count` در **سطحِ بالا** اضافه شد (نه داخلِ `data`). یعنی:

```jsonc
{
  "data": [
    {
      "device_slug": "washing-machine",
      "device_name": "ماشین لباسشویی",
      "device_label": "تعمیر ماشین لباسشویی بوش – آبگیری نمی‌کند",  // برندِ سازگار + مشکلِ واقعی
      "brand": "بوش",
      "brand_slug": "bosch",
      "brand_label": "بوش",
      "problem": "آبگیری نمی‌کند",
      "area": "تهران، سعادت‌آباد",
      "status": "completed",
      "minutes_ago": 6
    },
    {
      "device_slug": "refrigerator-freezer",
      "device_name": "یخچال و فریزر",
      "device_label": "تعمیر یخچال و فریزر",        // بدون برند و بدون مشکل — همیشه درست
      "brand": null, "brand_slug": null, "brand_label": null,
      "problem": null,
      "area": "تهران، ونک",
      "status": "completed",
      "minutes_ago": 13
    }
  ],
  "today_count": 312
}
```

**کارِ فرانت:** فقط `json.today_count` را به‌جای فرمولِ محلی بخوانید (`data` بدون تغییر است، نیازی به مهاجرت به `data.items` نیست).
- اگر `today_count === null` بود (خطای نادر سمتِ سرور)، همان رفتارِ قبلی/پیش‌فرضِ خودتان را نگه دارید.
- فیلدِ جدیدِ `problem` (string | null) **اختیاری** است؛ چون از قبل داخلِ `device_label` آمده، اگر کاری نکنید چیزی نمی‌شکند. فقط اگر می‌خواهید مشکل را جدا/با استایلِ خاص نشان دهید از `problem` استفاده کنید.

## نکته
برای اینکه برندها در «فعالیت زنده» ظاهر شوند، باید ترکیب‌های مربوطه در پنل **«مدیریت صفحات ترکیبی»** فعال باشند. تا وقتی فعال نشده‌اند، آیتم‌ها بدون برند (فقط نام دستگاه) می‌آیند — که عمداً امن‌ترین حالت است.
