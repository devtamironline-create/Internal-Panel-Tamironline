# نامه به تیم توسعهٔ اپ تکنسین — سه تغییر ۱۴۰۵/۰۵/۲۵

**از:** تیم بک‌اند پنل — **موضوع:** حذف پیش‌نویس، هماهنگی بدون توضیح، پرداخت داخل اپ با برگشت خودکار

## ۱) مفهوم «پیش‌نویس» حذف شد

- «پایان سفارش» همیشه **نهایی** است: فاکتور و بدهی همان لحظه ساخته می‌شود.
- ورودی `save_as_draft` در `POST /orders/{id}/status` از این نسخه **نادیده گرفته می‌شود** — اگر اپ هنوز می‌فرستد خطا نمی‌گیرد، ولی اثری هم ندارد. UI پیش‌نویس (چک‌باکس/حالت ذخیرهٔ موقت) را از اپ حذف کنید.
- پیش‌نویس‌های قدیمیِ باقی‌مانده: سرور برایشان همچنان گذار «ثبت نهایی» (همان Completed) را در `allowed_transitions` برمی‌گرداند تا قفل نشوند — این تنها جایی است که اثر پیش‌نویس هنوز دیده می‌شود.

## ۲) هماهنگی = فقط تقویم، بدون توضیح اجباری

- برای وضعیت «هماهنگ شده» دیگر `description` الزامی نیست — فلوی درست: نتیجهٔ تماس → انتخاب روز/بازه از تقویم (`POST /orders/{id}/schedule-visit`) → تمام.
- اگر اپ فرم توضیح را قبل از تقویم نشان می‌دهد، حذفش کنید. `description` اگر ارسال شود همچنان ذخیره می‌شود (اختیاری).
- وضعیت‌هایی که توضیح اجباری دارند (بدون تغییر): معلق (`suspended`)، رد سفارش (`declined`)، ایاب و ذهاب (`transit`) — حداقل ۱۵ کاراکتر.

## ۳) شارژ کیف‌پول داخل اپ + برگشت خودکار — ⚠ اصلاحیهٔ ۱۴۰۵/۰۵/۲۶

**نسخهٔ قبلی این بخش اشتباه بود** (باز کردن صفحهٔ وبِ `tech/wallet/recharge` — آن صفحه سشنِ وب می‌خواهد که اپ ندارد و کاربر به صفحهٔ لاگین پرت می‌شد). فلوی درست:

**قدم ۱ — از داخل اپ، API شارژ را صدا بزنید (با همان توکن sanctum):**

```
POST /v1/technician/wallet/recharge
{ "amount": 500000, "return_url": "karbalad://wallet?refresh=1" }
```

پاسخ (درگاه زیبال):

```json
{ "success": true, "data": { "gateway": "zibal", "method": "GET", "payment_url": "https://gateway.zibal.ir/start/..." } }
```

**قدم ۲ —** `payment_url` را **در مرورگر خارجی / Custom Tab** باز کنید (نه WebView) — این مستقیم صفحهٔ بانک است؛ هیچ سشن و لاگینی لازم ندارد.

**قدم ۳ —** بعد از پرداخت (موفق/ناموفق/لغو)، صفحهٔ نتیجهٔ پنل **۳ ثانیه بعد خودکار** به `return_url` شما برمی‌گردد (+ دکمهٔ دستی «بازگشت به اپلیکیشن»)، با پارامترهای `payment=success|failed` و `reference={شماره پیگیری}`.

**قدم ۴ —** بعد از برگشت، موجودی را از `GET /v1/technician/wallet` بخوانید — پارامتر `payment` فقط برای UI فوری است، نه تصمیم مالی.

نکته‌ها:
- **امنیت**: `return_url` از allowlist عبور می‌کند — `karbalad://` و `tamironline://` و زیردامنه‌های https مجاز از قبل هستند؛ scheme دیگری خواستید اعلام کنید. لینک غیرمجاز بی‌سروصدا حذف می‌شود (شارژ کار می‌کند، فقط برگشت خودکار ندارد).
- اگر درگاه فعال پنل «ملت» باشد، پاسخ `{"gateway":"mellat","method":"POST","start_pay_url":...,"ref_id":...}` است — باید فرم POST با `RefId` بسازید و submit کنید؛ فعلاً درگاه فعال زیبال است.
- ضمناً از این نسخه، مهمانِ مسیرهای `tech/*` دیگر به لاگین ادمین نمی‌رود و به لاگین تکنسین هدایت می‌شود.

## ۴) روش دریافت وجه هنگام تکمیل سفارش — جدید ۱۴۰۵/۰۵/۲۶

هنگام «پایان سفارش»، تکنسین باید مشخص کند وجه را چطور می‌گیرد. فیلد جدید در `POST /orders/{id}/status`:

```
payment_collection: "cash" | "online"
```

- **cash (نقدی)** — تکنسین وجه را در محل می‌گیرد. سرور درگاه را برای این فاکتور کامل خاموش می‌کند: لینک پرداخت به مشتری نشان داده نمی‌شود، `payable=false`، و اگر کسی صفحهٔ پرداخت را باز کند پیام «تسویهٔ نقدی در محل» می‌بیند.
- **online (اعتباری)** — مشتری آنلاین می‌پردازد. **UI اپ باید همین‌جا به تکنسین هشدار قاطع بدهد:**
  > ⚠️ پرداخت اعتباری انتخاب شد — به هیچ عنوان وجه نقد از مشتری دریافت نکنید. لینک پرداخت آنلاین برای مشتری فعال می‌شود.

  (پیشنهاد: confirm دومرحله‌ای قبل از ثبت.)
- فیلد فعلاً **nullable** است تا نسخه‌های قدیمی اپ نشکنند — نفرستادنش یعنی رفتار قبلی (درگاه باز). در UI جدید انتخابش را **اجباری** کنید؛ پیش‌فرض پیشنهادی: نقدی.
- در جزئیات فاکتورِ اپ مشتری هم `payment.collection_method` برگردانده می‌شود؛ برای فاکتور نقدی `pay_url`/`direct_pay_url` هر دو null هستند.
