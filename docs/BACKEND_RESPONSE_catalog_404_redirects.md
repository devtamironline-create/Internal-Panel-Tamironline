# پاسخِ بک‌اند به فرانت — مسیرهای خدمات و ریدایرکت‌های قدیمی

**تاریخ:** ۲۰۲۶-۰۹-۰۶ · **در پاسخِ:** «تعیین‌تکلیف مسیرهای خدمات و ریدایرکت‌های قدیمی»

ابزارِ داده ساخته شد: دستورِ فقط‌خواندنیِ **`php artisan seo:legacy-redirect-map`** که هر سه بخشِ دادهٔ درخواستیِ شما را تولید می‌کند (CSVِ ریدایرکت + وضعیتِ دو کامبو + منبعِ لینک‌های CMS). تفکیکِ device/brand از روی **اسلاگ‌های واقعیِ دیتابیس** انجام می‌شود (نه regexِ کور)، پس مواردِ چندکلمه‌ای مثل `side-by-side`, `wall-mounted-boiler`, `refrigerator-freezer`, `general-electric` درست جدا می‌شوند.

اجرا روی سرورِ پنل:
```bash
/opt/alt/php84/usr/bin/php artisan seo:legacy-redirect-map          # فقط اسلاگ‌های لاگِ ۴۰۴
/opt/alt/php84/usr/bin/php artisan seo:legacy-redirect-map --all    # + همهٔ *-repairهای قابلِ‌تولید
# CSV: storage/app/legacy-redirects.csv  (ستون‌ها: source,destination,status,hits)
```

## ۱) وضعیتِ دو کامبو (بخش ۱)

فکت‌های دیتابیس (از پنل):
| کامبو | دستگاه | برند | صفحهٔ ترکیبی | در sitemap؟ | API |
|---|---|---|---|---|---|
| `vacuum-cleaner`×`philips` | موجود ✓ | موجود ✓ | **ندارد** (منتشر نشده) | خیر | `/v1/catalog/devices/vacuum-cleaner/philips` → **۴۰۴ درست** |
| `wall-mounted-boiler`×`lorch` | موجود ✓ | موجود ✓ (فقط water-heater/lorch منتشر) | **ندارد** | خیر | `/v1/catalog/devices/wall-mounted-boiler/lorch` → **۴۰۴ درست** |

> فکت‌های دقیقِ رکورد (پیش‌نویس/فعال/طولِ محتوا) در خروجیِ همان دستور، بخشِ «وضعیتِ دو کامبو» می‌آید.

**تصمیمِ الف/ب/ج تصمیمِ کسب‌وکار است** (آیا مجموعه این خدمت را می‌دهد؟). داده‌ها این را می‌گویند: هیچ‌کدام صفحهٔ منتشرشده ندارند، پس فرانت درست ۴۰۴/noindex می‌کند. پیشنهادِ ما برای تصمیم:
- **philips × vacuum-cleaner:** فیلیپس جاروبرقی تولید می‌کند و احتمالِ ارائهٔ خدمت هست → اگر بله، ادمین صفحهٔ ترکیبی را **منتشر کند** (الف)؛ بعد از انتشار، API همان ۲۰۰ با محتوا می‌دهد و خودکار وارد sitemap/لینک‌ها می‌شود. اگر خیر → (ج) کاری لازم نیست.
- **lorch × wall-mounted-boiler (پکیج لورچ):** لورچ در پنل فقط با `water-heater` کامبو دارد. اگر «پکیج لورچ» محصولِ واقعی نیست → **(ج) واقعاً ناموجود**. ریدایرکت به `water-heater/lorch` را **نمی‌زنیم** مگر مالک صراحتاً تأیید کند (دستگاهِ متفاوت است؛ هم‌نظر با خودتان).

منتظرِ تصمیمِ مالک برای این دو می‌مانیم؛ سمتِ کدِ بک‌اند کاری لازم نیست جز انتشارِ صفحه در صورتِ (الف).

## ۲) فهرستِ ریدایرکت‌های قدیمی (بخش ۲)
خروجیِ `seo:legacy-redirect-map` دقیقاً جدولِ درخواستیِ شماست:
- `status = published` → مقصد امن و ۲۰۰ است؛ آمادهٔ ریدایرکت.
- `status = valid-but-unpublished` → device/brand واقعی‌اند ولی صفحه منتشر نشده؛ **ریدایرکت نزنید** تا ادمین منتشر کند (وگرنه ۳۰۱ به ۴۰۴).
- `status = unresolved` → با اسلاگ‌های فعلی قابلِ‌تفکیک نیست؛ برای بررسیِ دستی.

**نکتهٔ مهمِ منبعِ واحد:** پنل از قبل جدولِ `seo_redirects` و اندپوینتِ `GET /v1/seo/redirects` را دارد که **middleware.tsِ خودِ شما مصرف می‌کند**. پیشنهاد: به‌جای hardcode در `legacy-redirects.ts`، ریدایرکت‌های تأییدشده را در همان `seo_redirects` بگذاریم (از پنل مدیریت شوند) تا قانونِ موازی/متناقض ساخته نشود. اگر این را می‌خواهید، می‌توانم به دستور یک حالتِ `--write` اضافه کنم که ردیف‌های `published` را در `seo_redirects` درج کند (پس از تأییدِ شما). فعلاً CSV را می‌دهیم تا خودتان تصمیم بگیرید.

## ۳) منبعِ ۴ لینکِ داخلی به `/services/vacuum-cleaner/philips` (بخش ۳)
همان دستور، بخشِ «لینک‌های CMS»، محتوای مقالات (`site_blog_articles.content`) را برای این لینک و لینکِ لورچ اسکن می‌کند و **id/عنوانِ مقالهٔ مبدأ** را می‌دهد. اگر خروجی خالی بود، این ۴ لینک در محتوای CMS نیستند و به‌احتمالِ زیاد بازماندهٔ خزشِ قدیمیِ Atlas‌اند که با ۴۰۴ شدنِ صفحه (پس از دیپلوی + purge) خودبه‌خود پاک می‌شوند. (بازنویسیِ متنِ مقاله در این فاز با مسئولِ محتواست، نه ما.)

## ۴) purge کش CDN (بخش ۴)
- سمتِ پنل: فایل‌های سایت‌مپ ۲۰۰ و غیرخالی‌اند و کشِ سمتِ سرور دارند؛ در صورت نیاز `php artisan seo:sitemap-flush`.
- سمتِ WCDN: **purge** برای `/sitemap.xml` و همهٔ `/sitemaps/sitemap-*.xml` را تیمِ زیرساخت انجام دهد (دسترسیِ WCDN لازم است؛ از پنل قابل‌انجام نیست).

## خلاصهٔ اقدام
- **بک‌اند انجام داد:** دستورِ دادهٔ ریدایرکت/کامبو/CMS (فقط‌خواندنی، تفکیکِ امنِ چندکلمه‌ای) + تأییدِ فکت‌های دو کامبو + قراردادِ ۴۰۴ درست API.
- **منتظرِ مالک/فرانت:** تصمیمِ الف/ب/ج برای دو کامبو؛ انتخابِ محلِ ریدایرکت (`seo_redirects` پنل یا `legacy-redirects.ts` فرانت).
- **زیرساخت:** purge WCDN.
