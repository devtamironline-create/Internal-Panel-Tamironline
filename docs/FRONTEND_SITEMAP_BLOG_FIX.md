# نامهٔ بک‌اند به تیمِ فرانت — رفعِ سایت‌مپِ بلاگ (blog-1 / blog-2)

**تاریخ:** ۲۰۲۶-۰۹-۰۶ · **موضوع:** ۴۰۴ بودنِ `sitemap-blog-1.xml`/`sitemap-blog-2.xml` روی tamironline.com

## جمع‌بندی (یک‌خطی)
مشکل **سمتِ فرانت** است، نه بک‌اند. پنل هر دو فایلِ بلاگ را **سالم و غیرخالی** تولید و سرو می‌کند؛ فرانت این‌ها را نه پروکسی می‌کند و نه با نامِ درست می‌سازد.

## شواهدِ اندازه‌گیری‌شده (GET واقعی، از خودِ سرور — ۲۰۲۶-۰۹-۰۶)
| آدرس | HTTP | تعداد `<loc>` |
|---|---|---|
| `panel.tamironline.com/v1/seo/sitemaps/sitemap-blog-1.xml` | **200** | **۲۲۷** |
| `panel.tamironline.com/v1/seo/sitemaps/sitemap-blog-2.xml` | **200** | **۲۲۷** |
| `tamironline.com/sitemaps/sitemap-blog-1.xml` | **404** | 0 |
| `tamironline.com/sitemaps/sitemap-blog-2.xml` | **404** | 0 |
| `tamironline.com/sitemaps/sitemap-blog.xml` (تک، بدونِ شماره) | 200 | **0 (خالی)** |

- دادهٔ بک‌اند: ۴۵۴ مقالهٔ منتشرشده؛ ساختِ هر فایلِ بلاگ در پنل ~۰٫۶ ثانیه.
- شش فایلِ دیگر (core/local/services-devices/services-combo/brands/forum) روی فرانت ۲۰۰ هستند، ولی از **کشِ کهنهٔ CDN** (`wcdn-status: Hit`, `stale-while-revalidate=86400`) — یعنی با انقضای کش، آن‌ها هم در خطرِ ۴۰۴ شدن‌اند اگر ریشهٔ مشکل رفع نشود.

## علت
فرانت (Next.js) سایت‌مپ‌ها را **خودش تولید/سرو می‌کند** و:
1. فقط روتِ `sitemap-blog.xml` (تک) دارد؛ روتِ `sitemap-blog-1.xml` و `sitemap-blog-2.xml` را **ندارد** → ۴۰۴.
2. خروجیِ همان `sitemap-blog.xml` هم **خالی** است (دادهٔ بلاگ را درست از پنل نمی‌گیرد).
3. ایندکسِ اصلی (`sitemap.xml`) به `blog-1`/`blog-2` اشاره می‌کند (نام‌گذاریِ استانداردِ پنل) ولی فرانت این دو نام را سرو نمی‌کند → ناهماهنگیِ ایندکس ↔ فایل.

## راه‌حلِ پیشنهادی (به‌ترتیبِ اولویت)

### گزینهٔ A (توصیه‌شده) — پروکسیِ مستقیم به پنل (منبعِ واحد)
سایت‌مپ را در فرانت **نساز**؛ این مسیرها را عیناً به پنل rewrite/proxy کن:
```
tamironline.com/sitemap.xml
   → panel.tamironline.com/v1/seo/sitemap.xml
tamironline.com/sitemaps/sitemap-{name}.xml
   → panel.tamironline.com/v1/seo/sitemaps/sitemap-{name}.xml
```
مزایا: همیشه هم‌راستا با پنل، بدونِ ناهماهنگیِ نام، بدونِ منطقِ تکراری. پنل خودش کش + «آخرین نسخهٔ سالم» دارد (نسخهٔ جدیدِ بک‌اند).

### گزینهٔ B — اگر فرانت حتماً باید خودش بسازد
1. روت‌های `sitemap-blog-1.xml` و `sitemap-blog-2.xml` را اضافه کن (نام دقیقاً مطابقِ ایندکس).
2. علتِ خالی‌بودنِ دادهٔ بلاگ را رفع کن — منبعِ داده همان چیزی است که پنل استفاده می‌کند (مقالاتِ `published_at ≤ now`، بدونِ noindex، canonical-self). اگر از API پنل می‌خوانی و خطا/خالی می‌گیری، عینِ درخواست/پاسخ را بفرست تا بررسی کنیم.
3. روتِ بی‌استفادهٔ `sitemap-blog.xml` (تک) را یا حذف کن یا با ایندکس هماهنگ کن.

## نکتهٔ CDN
پس از اصلاحِ فرانت، کشِ CDN را برای `sitemap.xml` و همهٔ `sitemaps/sitemap-*.xml` **purge** کنید تا نسخهٔ درست بلافاصله سرو شود (وگرنه ۴۰۴/خالیِ کهنه تا ۲۴ ساعت می‌ماند).

## معیارِ پذیرش
- `tamironline.com/sitemaps/sitemap-blog-1.xml` و `-2.xml` → **200 و غیرخالی** (هرکدام ~۲۲۷ URL، جمعِ ~۴۵۴).
- ایندکسِ `sitemap.xml` فقط به فایل‌هایی اشاره کند که واقعاً ۲۰۰ و غیرخالی برمی‌گردانند.
- در چند درخواست با فاصله، پاسخ پایدار بماند.

## سمتِ بک‌اند
کارِ جدیدی لازم نیست. پنل همهٔ ۸ فایل را درست سرو می‌کند و اکنون کشِ سمتِ سرور + «آخرین نسخهٔ سالم» هم دارد (`php artisan seo:sitemap-flush` برای refreshِ فوری). API/داده آماده است.

با احترام — تیم بک‌اند (پنل)
