- **پیشوندِ `/city/`** — در `sitemap-local.xml`، `breadcrumbs[].path` و canonical

- **کلیدِ ریشه‌ای برای کوئری‌ها** — `?path=` و `?slug=` و `data.path` ریشه‌ای

- **کلیدهای `sections_enabled`** هم‌نام شد: `hero, activity, steps, content,
  pricing, faq, brands, otherDevices, videos, forum, related, testimonials,
  promo, links`.
- **عکسِ Hero** سمتِ سرور resolve می‌شود؛ فقط `hero_image.mobile` را بخوانید.
- **slugها انگلیسی** شدند (کرج → `karaj`) و مسیرها از همان ساخته می‌شوند.
- **`children`** برای صفحاتِ فهرستی اضافه شد (برای گریدِ کارت‌ها).

## ⚠️ اقداماتِ لازم سمتِ شما (Next.js)

### 🔴 بحرانی — بدنهٔ صفحه = `content`ِ صفحهٔ شهری
ادمین برای `/karaj/services/washing-machine` محتوا می‌نویسد ولی سایت محتوایِ
عمومیِ «لباسشویی» را نشان می‌دهد.
- اگر `content`ِ صفحهٔ شهری **غیرخالی** بود → همان بدنهٔ صفحه است (جایگزینِ کاتالوگ).
- فقط اگر **خالی/null** بود → به محتوای کاتالوگِ دستگاه/برند fallback شود.
- به‌طور کلی برای صفحاتِ شهری، اولویت همیشه با فیلدهای `payload`ِ city است؛
  کاتالوگ فقط fallback + منبعِ سکشن‌های مشترک (FAQ/نظرات).

### 🔴 بحرانی — صفحاتِ فهرستی مثلِ `/services` رِندر شوند
`/city/karaj/services` الان تقریباً خالی است؛ باید مثلِ `/services` باشد
(هیرو + گریدِ کارت‌ها + سکشن‌های مشترک).
- payloadِ صفحاتِ فهرستی (services / city / brands) حالا آرایهٔ `children` دارد
  (فقط منتشرشده‌ها).
- گرید را از `children` بسازید: کارت + لینکِ `/city{path}`؛ تصویرِ کارت از
  کاتالوگِ همان `device`/`brand`.
- `services` و `city` → فرزندانِ دستگاه؛ `brands` → فرزندانِ برند.

### 🟡 اقدام — متغیرهای پویا در محتوای مشترک
توکن‌های `{city}` / `{device}` / `{brand}` / `{province}` در فیلدهای خودِ صفحه
را **بک‌اند** resolve می‌کند. اما در محتوایی که از کاتالوگ می‌آید (بدنهٔ FAQ،
سوال/جواب، نظرات) **شما** باید همین توکن‌ها را با contextِ شهر جایگزین کنید.
مثال: «آیا در {city} خدمات دارید؟» روی صفحهٔ مشهد ← «آیا در مشهد خدمات دارید؟».

### 🟡 اقدام — سکشن‌های خاموش را نسازید
هر کلیدِ `sections_enabled` که `false` است رِندر نشود؛ `null` یعنی همه روشن.

## 🔌 خلاصهٔ قرارداد API

| کار | endpoint |
|---|---|
| فهرست | `GET /v1/customer/seo/city-pages` · فیلترِ `?city=mashhad` |
| یک صفحه | `GET /v1/customer/seo/city-pages?path=/mashhad/...` · منتشرنشده = `404` |
| متا/اسکیما | `GET /v1/seo/meta?type=city_page&slug=/mashhad/...` |
| Sitemap | `sitemap-local.xml` (URLها `/city/`-دار) |

هر فیلدِ عمومیِ payload (title/h1/subtitle/caption/content/hero/breadcrumbs/
children/sections) برای صفحهٔ شهری بر کاتالوگ اولویت دارد.
