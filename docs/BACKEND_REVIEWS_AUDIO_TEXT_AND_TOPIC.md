# نامه به تیم فرانت — نظرات/توصیه‌نامه‌ها: (۱) موضوعِ placeholderدار، (۲) صوت + متن هم‌زمان

> نسخه: 1.0 | همه‌ی تغییرات backward-compatible هستند.

## ۱) موضوع (`topic`) حالا سمتِ سرور جایگزین می‌شود

قبلاً موضوعِ بعضی توصیه‌نامه‌ها مثل `«تعمیر {device}»` با placeholderِ خام برمی‌گشت و در فرانت `{device}` دیده می‌شد. **حالا سرور این placeholderها را بر اساس صفحه‌ای که نظر در آن سرو می‌شود جایگزین می‌کند:**

- در صفحه‌ی دستگاه و `/v1/testimonials?device={slug}` → `{device}`، `{device_label}`، `{device_slug}`
- در صفحه‌ی برند → `{brand}`، `{brand_slug}`
- در صفحه‌ی ترکیبی → همه‌ی موارد بالا

**کارِ فرانت:** فقط `topic` را همان‌طور که هست نمایش بده — دیگر نیازی به جایگزینی سمتِ کلاینت نیست. (اگر جایی خودت `{device}` را جایگزین می‌کردی، حذفش کن.)

## ۲) هر نظر می‌تواند «صوت»، «متن»، یا «هر دو» باشد

ادمین حالا می‌تواند برای یک توصیه‌نامه هم **فایل صوتی** و هم **متن** ثبت کند. بنابراین در پاسخِ API هر آیتم می‌تواند هم‌زمان `audio_url` و `content` داشته باشد:

```json
{
  "id": "01J...",
  "type": "audio",
  "author_name": "علی رضایی",
  "topic": "تعمیر لباسشویی",
  "rating": 5,
  "audio_url": "https://panel.tamironline.com/media/123/voice.mp3",
  "duration_seconds": 47,
  "content": "خیلی سریع و حرفه‌ای تعمیر شد، ممنون."
}
```

**کارِ فرانت — رندر بر اساسِ «وجودِ فیلد»، نه بر اساسِ `type`:**
- اگر `audio_url` پر است → پخش‌کننده‌ی صوت را نشان بده.
- اگر `content` پر است → متن را نشان بده.
- اگر **هر دو** پر است → هر دو را نشان بده (پخش‌کننده + متن).

> چرا بر اساس `type` نه؟ چون `type` صرفاً منبعِ ثبت را مشخص می‌کند (`audio` = ساخته‌ی ادمین، `text` = ارسالِ فرم عمومی)، نه نوعِ محتوا. یک آیتمِ `type: "audio"` ممکن است فقط متن داشته باشد یا برعکس.

### endpointهای متأثر
| Endpoint | تغییر |
|----------|-------|
| `GET /v1/testimonials` | حالا `content` هم برمی‌گرداند + `topic` جایگزین‌شده |
| `GET /v1/catalog/devices/{slug}` → `sections.testimonials.items` | `topic` جایگزین‌شده (audio_url/content از قبل بود) |
| `GET /v1/catalog/brands/{slug}` → `sections.testimonials.items` | `topic` جایگزین‌شده |
| `GET /v1/catalog/devices/{device}/{brand}` → `sections.testimonials.items` | `topic` جایگزین‌شده |

## ۳) درباره‌ی «پخش نشدنِ صوت»
علتِ رایج: `audio_url`ای که قبلاً ثبت شده **آدرسِ مستقیمِ فایل** نبوده (مثلاً لینکِ صفحه‌ی اشتراک‌گذاری). از این پس ادمین می‌تواند فایل صوتی را مستقیم در پنل **آپلود** کند و یک URLِ مستقیم و قابلِ‌پخش (`/media/...`) ذخیره می‌شود. اگر مورد قدیمی‌ای هنوز پخش نمی‌شود، در پنل دوباره فایلش را آپلود کنید.

- میزبانِ فایل‌ها: `panel.tamironline.com` (در `remotePatterns`/CSPِ صوت مجاز باشد).
- برای `<audio>` از خودِ `audio_url` به‌عنوان `src` استفاده کنید (mp3/m4a/ogg).
