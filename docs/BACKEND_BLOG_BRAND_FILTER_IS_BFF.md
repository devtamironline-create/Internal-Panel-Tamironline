# پاسخ به نامه‌ی فرانت — فیلتر `brand` در بلاگ: بک‌اند درست است، مشکل در BFF/فرانت

> وضعیت: بک‌اند تأیید شد ✅ | اقدام لازم: سمت Next/BFF

## خلاصه

فیلترِ `brand` در `GET /v1/blog/articles` **درست کار می‌کند**. روی دادهٔ واقعیِ production:

```
کل مقالاتِ منتشرشده: 445
GET /v1/blog/articles?brand=lg   → meta.total = 27   (نه 445)
GET /v1/blog/articles?brand=bosch → 50
GET /v1/blog/articles?brand=samsung → 37
```

پس بک‌اند فقط مقالاتِ همان برند را برمی‌گرداند. اگر صفحه‌ی `/blog?brand=lg` همه‌ی مقالات را نشان می‌دهد، پارامتر `brand` **به این درخواستِ بک‌اند نمی‌رسد** یا یک **کش** پاسخِ بدونِ‌فیلتر را سرو می‌کند. این بین مرورگر↔BFF↔بک‌اند است، نه در کوئریِ بک‌اند.

(تأیید فنی: منطق `whereHas('activeBrands', slug=...)` دقیقاً متقارنِ `device`/`topic` است و در تستِ ایزوله هم درست فیلتر می‌کند. خروجیِ ۲۷/۴۴۵ هم همین را روی دادهٔ واقعی نشان می‌دهد.)

## چه چیزی را در فرانت/BFF چک کنید (به‌ترتیب احتمال)

1. **آیا `brand` به فراخوانِ بک‌اند می‌رسد؟**
   در Network tab ببینید درخواستی که BFF به بک‌اند می‌زند (یا `/api/...` داخلی) واقعاً `…/v1/blog/articles?...&brand=lg` است یا `brand` حذف شده. اگر در فراخوانِ بک‌اند `brand` نیست → مشکلِ فوروارد است.

2. **فوروارد کاملِ query string:**
   هندلرِ BFF برای بلاگ باید **همه‌ی** پارامترها (`topic, device, brand, q, page, limit, sort`) را عبور دهد. اگر فقط زیرمجموعه‌ای (مثلاً `topic` و `device`) را map می‌کند، `brand` می‌افتد. (این دقیقاً با «device کار می‌کند ولی brand نه» می‌خواند.)

3. **کلیدِ کش شاملِ `brand` باشد:**
   اگر از `fetch(url, { next: { revalidate/tags } })`، `unstable_cache`، یا full-route cache استفاده می‌کنید، مطمئن شوید **کلیدِ کش به `brand` وابسته است**. اگر صفحه بر اساس `searchParams` استاتیک کش شده، نسخه‌های `?brand=` مختلف ممکن است همان HTMLِ بدونِ‌فیلتر را بگیرند. راه‌حل: صفحه را به `searchParams` وابسته/داینامیک کنید یا `brand` را در کلیدِ کش بگذارید.

4. **خواندنِ صحیحِ searchParams:**
   مطمئن شوید صفحه `searchParams.brand` را می‌خواند و **در URLِ fetchِ بک‌اند** می‌گذارد (نه فقط برای UI).

## تستِ سریعِ تعیین‌کننده

مستقیماً بک‌اند را صدا بزنید (بدونِ عبور از BFF/کش) و `meta.total` را ببینید:
```
GET https://<backend>/v1/blog/articles?brand=lg&limit=12
→ meta.total باید 27 باشد
```
- اگر ۲۷ بود (که هست) و صفحه‌ی سایت ۴۴۵ نشان می‌دهد → مشکل قطعاً در BFF/کش است.

## ابزار سمتِ بک‌اند برای راستی‌آزمایی
`php artisan blog:filter-check --brand=lg` و `php artisan blog:filter-check --top-brands` (read-only) — همان کوئریِ endpoint را روی دادهٔ واقعی اجرا می‌کنند.
