# نامه به تیم توسعه سایت — «مناطق تحت پوشش» و عناوین آن (۱۴۰۵/۰۶/۰۳)

**از:** تیم بک‌اند پنل — **موضوع:** پیاده‌سازی نمایش استان‌ها/شهرهای تحت پوشش هر خدمت با عناوین قابل‌مدیریت کارفرما

---

## ۱) تصویر کلی — چه چیزی ساخته شده و شما چه می‌سازید

کارفرما در پنل دو چیز را مدیریت می‌کند و شما فقط **مصرف‌کننده** هستید:

1. **پوشش واقعی** (کدام خدمت در کدام استان/شهر/منطقه فعال است): خودکار از تگ‌های
   تکنسین‌های فعال + کنترل «نمایش در سایت» ادمین. هیچ لیست شهری را hardcode نکنید.
2. **عناوین نمایش** (صفحهٔ «عناوین مناطق تحت پوشش» هر خدمت): ردیف‌هایی از
   «پیشوند + برندِ اختیاری + حرف اضافه» که شما برای هر مکانِ تحت پوشش به عنوان
   تبدیل می‌کنید.

هر دو از **یک** endpoint می‌آیند:

```
GET https://panel.tamironline.com/v1/customer/seo/coverage
```

(public، JSON، سمت پنل ۱۵ دقیقه کش می‌شود + هدر `Cache-Control: public, max-age=3600`.
سمت خودتان ۱ تا ۲۴ ساعت کش کنید و اگر endpoint در دسترس نبود از آخرین کش استفاده کنید.)

## ۲) ساختار داده‌ای که می‌گیرید

```jsonc
{
  "data": {
    "coverage_data_complete": true,   // ⚠ اگر false بود هیچ‌چیز را بر اساس این خروجی تغییر ندهید
    "services": [
      {
        "id": 1,
        "name": "لباسشویی",
        "slug": "washing-machine",
        "province_count": 2,
        "city_count": 3,
        "provinces": [
          {
            "province_id": 8,
            "name": "تهران",
            "cities": [
              // ترتیب از قبل «مرکز استان اول» است — همین ترتیب را حفظ کنید
              { "city_id": 102, "name": "تهران", "slug": "tehran",
                "technician_count": 12, "brands": "all", "site_visible": true }
            ]
          },
          {
            "province_id": 11,
            "name": "خراسان رضوی",
            "cities": [
              { "city_id": 240, "name": "مشهد", "slug": "mashhad",
                "technician_count": 2, "brands": ["samsung"], "site_visible": true }
            ]
          }
        ],
        "titles": [
          { "prefix": "تعمیر",  "brand": "bosch", "brand_name": "بوش",  "preposition": "در" },
          { "prefix": "خدمات",  "brand": null,     "brand_name": null,   "preposition": "برای" }
        ]
      }
    ],
    "cities": [ /* نمای شهرمحور — برای areaServed در Schema (قبلاً تحویل شده) */ ],
    "devices": [ /* کاتالوگ خدمات */ ],
    "brands": [ { "name": "سامسونگ", "slug": "samsung" } ]
  }
}
```

نکته‌ها:
- خدمتی که در `services` نیست = هیچ‌جا پوشش ندارد → در سایت برایش هیچ ادعای
  پوشش/صفحهٔ محلی نسازید.
- شهر/خدمتی که ادمین «مخفی از سایت» کرده اصلاً در این خروجی نمی‌آید — لازم نیست
  خودتان فیلتر کنید.
- `titles` هرگز خالی نیست: اگر کارفرما چیزی نساخته باشد یک ردیف پیش‌فرض
  `{"prefix":"تعمیر","brand":null,"preposition":"در"}` می‌آید.

## ۳) قاعدهٔ ساخت عنوان (قلب این نامه)

برای هر ردیف `titles` و هر مکانِ تحت پوشش:

```
{prefix} {نام خدمت} {brand_name؟} {preposition} {نام مکان}
```

مثال‌ها با دادهٔ بالا:
- ردیف ۱ + شهر تهران ← **«تعمیر لباسشویی بوش در تهران»**
- ردیف ۲ + استان خراسان رضوی ← **«خدمات لباسشویی برای خراسان رضوی»**
- ردیف بدون برند + شهر مشهد ← «خدمات لباسشویی برای مشهد»

قواعد الزامی:
1. **ترتیب آرایهٔ `titles` = ترتیب نمایش در سایت.** (کارفرما با drag/↑↓ در پنل
   تعیین می‌کند.)
2. **ردیف برنددار فقط برای مکان‌هایی render شود که آن برند در آن شهر مجاز است:**
   `brands` همان شهر یا `"all"` باشد یا شامل slug آن برند. مثال: ردیف «بوش» برای
   مشهد ساخته **نمی‌شود** (مشهد فقط `["samsung"]` دارد) ولی برای تهران می‌شود.
3. «مکان» سه سطح دارد و هر سه از همین داده درمی‌آیند:
   - **استان:** `provinces[].name`
   - **شهر:** `provinces[].cities[].name`
   - **منطقه:** از نمای `cities[]` فیلد `districts` (فقط تهران/کرج منطقه دارند)
4. ترتیب شهرها را عوض نکنید — مرکز استان عمداً اول است.
5. فاصله‌گذاری سادهٔ تک‌spaceای؛ اجزای null حذف شوند (join روی اجزای موجود).

## ۴) کجاها استفاده کنید

| محل | چه چیزی |
|---|---|
| صفحهٔ هر خدمت (مثل «تعمیر لباسشویی») | سکشن «مناطق تحت پوشش»: آکاردئون استان ← شهرها؛ headingها از `titles` (حداقل ردیف اول) |
| صفحات ترکیبی خدمت+برند («لباسشویی سامسونگ») | فقط شهرهایی که برندشان مجاز است + عنوان از ردیفِ همان برند |
| صفحات محلی خدمت+شهر («تعمیر لباسشویی در مشهد») | title/H1 صفحه از ردیف اولِ مجاز برای آن شهر |
| Service Schema (`areaServed`) | مثل قبل از نمای `cities[]` — تغییری نکرده |

قانون همیشگی: **ترکیبی که در این خروجی نیست، صفحه/ادعا نگیرد** (ادعای خدمات بدون
ارائه = ریسک سئو و شکایت).

## ۵) کش و به‌روزرسانی

- سمت خودتان ۱–۲۴ ساعت کش + fallback به آخرین کش در خطا. hardcode ممنوع.
- هر تغییر کارفرما (عناوین، مخفی/نمایش، تگ تکنسین) حداکثر ۱۵ دقیقه بعد در endpoint
  منعکس است؛ اگر از `GET /v1/customer/status` استفاده می‌کنید، فیلد `cache_version`
  با هر تغییر جلو می‌رود و می‌توانید کش را فوری باطل کنید.

## ۶) معیار پذیرش

- [ ] سکشن «مناطق تحت پوشش» صفحات خدمت از `services[].provinces` رندر می‌شود (نه لیست دستی)
- [ ] عناوین دقیقاً با قاعدهٔ بخش ۳ ساخته می‌شوند و ترتیب `titles` حفظ می‌شود
- [ ] ردیف برنددار در شهرِ بدون آن برند render نمی‌شود
- [ ] ترتیب شهرها (مرکز استان اول) حفظ می‌شود
- [ ] گارد `coverage_data_complete=false` → متن/رفتار فعلی سایت بدون تغییر
- [ ] کش سمت سایت + عدم hardcode
- [ ] تست پذیرش با کارفرما: یک عنوان در پنل عوض شود → حداکثر با یک purge کش، سایت همان را نشان دهد

سوال فنی بود: خروجی واقعی را با یک `curl` از endpoint بگیرید؛ مرجع مقایسه برای
کارفرما صفحهٔ «افراد ← پوشش خدمات» پنل است.
