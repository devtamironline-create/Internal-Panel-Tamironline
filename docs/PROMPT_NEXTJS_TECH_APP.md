> فراهم کند (چون فعلاً API تکنسین وجود ندارد — پنل فعلی Blade/session است).

## ⚠️ پیش‌نیازِ حیاتی (قبل از شروعِ فرانت بخوان)
پنلِ تکنسینِ فعلی **سمتِ سرور رندر می‌شود** (Blade + `guard('tech')` با session) و
مدلِ `Technician` **توکنِ API نمی‌سازد** (بدون Sanctum `HasApiTokens`). پس یک اپِ
Next.js فعلاً چیزی برای اتصال ندارد. مسیرِ درست:
1. **بک‌اند اول:** یک API توکنی `/v1/technician/*` ساخته شود (احراز با توکنِ
   Sanctum روی مدلِ Technician + همهٔ endpointهای بخش «ب»).
2. **فرانت بعد:** اپِ Next.js با پرامتِ بخش «الف» ساخته شود و همان API را مصرف کند.

الگوی آمادهٔ بک‌اند: اپِ مشتری (`Modules/CustomerApp` + `Modules/Identity`) که با
OTP → توکنِ Sanctum کار می‌کند و کشویی‌کردنِ توکن با `X-Renewed-Token` دارد.
تکنسین می‌تواند همان الگو را با «موبایل + رمز» یا «موبایل + OTP» تکرار کند.

# بخش الف — پرامتِ ساختِ اپ (این را به ابزارِ AI بده)

نقش تو یک **Senior Frontend Engineer** متخصصِ Next.js و طراحِ محصولِ موبایل است.
یک **Progressive Web App (PWA) موبایل‌محور برای تکنسین‌های تعمیرآنلاین** بساز که
از طریقِ REST API به بک‌اند (Laravel) وصل می‌شود. زبانِ رابط **فارسی، کاملاً
RTL**، فونت **Vazirmatn**، تاریخ‌ها **شمسی (جلالی)**.

## هویتِ بصری و تجربهٔ کاربری
- موبایل‌فرست، تک‌ستونی، مثلِ یک اپِ نیتیو (نه سایت). قابلِ نصب (Add to Home Screen).
- زبانِ طراحی: مدرن، تمیز، کارت‌محور با گوشه‌های گرد (۲۰–۲۴px)، سایه‌های نرم.
- رنگِ برند: گرادیانِ آبی (`#1e3a8a → #1d4ed8`) برای هدرها/دکمه‌های اصلی؛ سبز
  (`#059669/#10b981`) برای تأیید/مالیِ مثبت؛ رزِ ملایم برای خطا/الزامی.
- ناوبریِ پایین (bottom tab bar): داشبورد، سفارش‌ها، کیف‌پول، آموزش، پروفایل.
- هدرِ Hero با گرادیان روی صفحاتِ اصلی؛ کارت‌های شناور که روی هدر همپوشانی دارند.
- حالتِ تاریک (dark mode) کامل. انیمیشن‌های ظریف (Framer Motion) برای گذارِ صفحات و
  ورودِ کارت‌ها. حالتِ‌های Loading (skeleton)، Empty، و Error برای هر صفحه.
- اعدادِ فارسی در نمایش؛ مبالغ با جداکنندهٔ هزارگان + «تومان» + مبلغ به حروف در
  فرم‌های مالی.
- دسترس‌پذیری: تارگت‌های لمسیِ ≥ ۴۴px، کنتراست کافی، فوکوسِ واضح.

## استکِ فنی (آخرین نسخه‌ها)

- **PWA** با **Serwist** (یا next-pwa): manifest، آیکن‌ها، آفلاین‌شل، کشِ درست

- تاریخِ شمسی: **dayjs + plugin jalali** یا **jalaali-js**. فونت: **Vazirmatn**
  (self-host، بدونِ CDN خارجی).
- **axios** یا fetch wrapper با اینترسپتورِ توکن.
- کیفیت: ESLint + Prettier + TypeScript strict؛ ساختارِ feature-based.

## احراز هویت و Session (مطابقِ الگوی بک‌اند)
- ورود: صفحهٔ «موبایل» → درخواستِ OTP → صفحهٔ «کدِ تأیید» با **autofill/WebOTP**
  (input با `autocomplete="one-time-code"` + `navigator.credentials.get({otp})`).
  (اگر بک‌اند به‌جای OTP از رمز استفاده کرد، فرمِ موبایل+رمز بگذار.)
- پاسخِ موفق یک **Bearer token** می‌دهد؛ در `localStorage` نگه‌دار.
- روی هر درخواست هدرِ `Authorization: Bearer <token>` بفرست.
- هر پاسخ ممکن است هدرِ **`X-Renewed-Token`** داشته باشد → توکن را جایگزین کن
  (session کشویی؛ کاربرِ فعال هیچ‌وقت خارج نشود).
- روی **۴۰۱** → logout و هدایت به صفحهٔ ورود. روی **۴۰۳/۵xx گذرا** → logout نکن؛
  خطای دوستانه نشان بده و اجازهٔ retry بده.
- `X-Device-ID` (یک UUID پایدارِ ذخیره‌شده) روی درخواست‌ها بفرست.

## صفحات و قابلیت‌ها (بر اساسِ پنلِ فعلیِ تکنسین)
1. **ورود** — موبایل → OTP/رمز → توکن.
2. **داشبورد** — تقویمِ ۷ روزِ پیشِ‌رو؛ هر روز تفکیک‌شده به بازه‌های ساعتی
   (۹–۱۲، ۱۲–۱۵، ۱۵–۱۸، ۱۸–۲۱) با شمارشِ سفارش‌ها؛ خلاصهٔ مالیِ هدر (بدهی به شرکت).
3. **لیستِ سفارش‌ها** — فیلترِ وضعیت، جست‌وجو، صفحه‌بندی، کارتِ آماری (کل/هماهنگ‌شده/
   باز/تکمیل). هر کارت: کد، مشتری، وضعیت (بَج رنگی)، زمانِ مراجعه.
4. **جزئیاتِ سفارش**:
   - کارتِ مشتری (تماسِ tel: — روی سفارشِ نهایی شماره ماسک‌شده و بدونِ لینک).
   - کارتِ آدرس + نقشه (اگر مختصات دارد: پیش‌نمایشِ OSM + دکمه‌های نشان/گوگل‌مپ/بلد).
   - کارتِ دستگاه و عیب.
   - یادداشت‌های تکنسین + افزودنِ یادداشت.
   - **تاریخچهٔ وضعیت** (بدونِ نامِ تغییردهنده — فقط تاریخِ شمسی).
5. **تغییرِ وضعیت** — رادیوهای مجاز: هماهنگ‌شده، انتقال به تعمیرگاه، وضعیتِ نامشخص،
   پایان سفارش، رد سفارش، فقط ایاب‌وذهاب. توضیحِ وابسته به وضعیت (بعضی الزامی).
   - «انتقال به تعمیرگاه»: توضیح اختیاری؛ سرور خودکار **رسیدِ انتقال** می‌سازد و
     لینکش را برای مشتری پیامک می‌کند (اپ فقط وضعیت را ثبت می‌کند).
   - «پایان سفارش»: بلاکِ فاکتور — کل مبلغِ مشتری (با نمایشِ مبلغ به حروف)، لیستِ
     قطعات (نام + قیمتِ خرید)، عکسِ دستگاهِ پس‌از‌تعمیر (اجباری مگر برگشتی/پیش‌نویس)،
     توضیحاتِ فاکتور، محاسبهٔ زندهٔ «سهم شما» و «مانده پس از کسرِ قطعات»، و قاعدهٔ
     «جمع فاکتور ≥ هزینهٔ قطعات». چک‌باکسِ «ذخیره به‌عنوان پیش‌نویس».
6. **هماهنگیِ زمانِ مراجعه** — انتخابِ روز (۷ روز) + بازهٔ ساعت؛ ثبت/پاک‌کردن.
7. **پیش‌فاکتور** — لیست + ساختِ پیش‌فاکتور (اقلام، تخفیف) و ارسالِ لینک به مشتری.
8. **کیف‌پول** — تراکنش‌ها (کمیسیون/پاداش/جریمه/شارژ) با فیلتر و مجموع‌ها؛ **شارژ از
   درگاه** (Zibal/ملت) با redirect و بازگشت.
9. **فاکتورها** — لیستِ فاکتورهای تکنسین با آمار (تعداد/جمع/سهمِ تکنسین/سهمِ شرکت).
10. **آموزش** — دسته‌ها → ویدیوها؛ علامتِ «دیده‌شد»؛ گِیتِ فعال‌سازیِ پنل تا دیدنِ
    همهٔ ویدیوها (اگر بک‌اند این قید را برمی‌گرداند).
11. **پروفایل** — مشاهدهٔ اطلاعات، آپلودِ آواتار (یک‌بار)، تغییرِ رمز.
12. (اختیاری) **تیکت/اعلان/پیام‌رسان** اگر API فراهم شد.

## قواعدِ رفتاری
- همهٔ تغییرها optimistic با rollback روی خطا؛ پس از موفقیت، کوئری‌های مرتبط را
  invalidate کن.
- فرم‌های مالی: محاسبهٔ زنده سمتِ کلاینت، ولی **سرور منبعِ حقیقت است** (مقدارِ
  برگشتی را نمایش بده).
- هرگز اطلاعاتِ تماسِ مشتری را روی سفارشِ نهایی نمایشِ کاملِ قابلِ‌تماس نده.
- تایم‌زون Asia/Tehran؛ تاریخ‌ها را از ISO-8601 UTC بگیر و شمسی نمایش بده.

## خروجی
- پروژهٔ کاملِ Next.js با ساختارِ تمیز، متغیرهای محیطی (`NEXT_PUBLIC_API_BASE_URL`)،

# بخش ب — قراردادِ API که بک‌اند باید فراهم کند

> این‌ها **هنوز وجود ندارند** و باید ساخته شوند (الگو: CustomerApp v1). همه زیرِ
> `/api/bff/v1/technician` (یا معادل)، با `auth:sanctum` روی مدلِ Technician،
> میدل‌ورِ RollingToken، و پاسخِ استانداردِ `{ success, data }`.

### احراز
- `POST /v1/technician/auth/send-otp` — `{ mobile }` → ارسالِ OTP.
- `POST /v1/technician/auth/verify-otp` — `{ mobile, code }` → `{ token, technician }`.
  (یا `POST /auth/login` با `{ mobile, password }` اگر رمزی می‌مانید.)
- `POST /v1/technician/auth/logout` — ابطالِ توکنِ فعلی.
- `GET  /v1/technician/me` — پروفایلِ تکنسینِ لاگین‌شده.

### سفارش‌ها
- `GET  /v1/technician/orders?status=&q=&page=` — لیست + آمار + صفحه‌بندی.
- `GET  /v1/technician/orders/{id}` — جزئیات (مشتری/آدرس/مختصات/دستگاه/عیب/
  یادداشت‌ها/تاریخچهٔ وضعیت/گذارهای مجاز/پیش‌فاکتورها/رسیدهای انتقال).
- `POST /v1/technician/orders/{id}/status` — تغییرِ وضعیت (+ فیلدهای فاکتور هنگام
  Completed، آپلودِ عکس multipart).
- `POST /v1/technician/orders/{id}/schedule-visit` — `{ visit_date, visit_slot }`.
- `POST /v1/technician/orders/{id}/notes` — `{ note }`.
- `POST /v1/technician/orders/{id}/deliver-sms` — پیامکِ «آماده تحویل» (اگر مجاز).

### پیش‌فاکتور / رسیدِ انتقال
- `GET  /v1/technician/proformas?order_id=` , `POST /v1/technician/proformas`
  (اقلام، تخفیف) , `POST /v1/technician/proformas/{id}/send`.
- رسیدِ انتقال خودکار هنگامِ وضعیتِ Open ساخته می‌شود؛ در جزئیاتِ سفارش
  `transfer_receipts[]` (code, description, print_url) برگردد.

### کیف‌پول / فاکتور / آموزش / پروفایل
- `GET /v1/technician/wallet?type=` (+ آمار) ، `POST /v1/technician/wallet/recharge`
  (مبلغ → لینکِ درگاه) و callbackِ موجودِ درگاه.
- `GET /v1/technician/invoices?status=` (+ آمار).
- `GET /v1/technician/training` ، `GET /training/{video}` ،
  `POST /training/{video}/watched` (+ progress).
- `POST /v1/technician/profile/avatar` (یک‌بار) ، `POST /v1/technician/profile/password`.

### قراردادهای عمومی
- احراز: `Authorization: Bearer <token>`؛ تمدید: هدرِ `X-Renewed-Token` روی هر
  پاسخِ موفق. خطاها: `401` = session مرده (logout)، `422` = اعتبارسنجی، `403` =
  عدم‌دسترسی (بدونِ logout).
- تاریخ‌ها ISO-8601 UTC؛ مبالغ به تومان (integer).
