# اپ — رسیدِ انتقالِ دستگاه به تعمیرگاه (Transfer Receipt)

وقتی تکنسین دستگاه را از محلِ مشتری برای تعمیر به تعمیرگاه منتقل می‌کند، یک
«رسیدِ انتقال» روی همان سفارش ثبت می‌شود و لینکش با پیامک برای مشتری می‌رود.
**این سند برای تیمِ توسعهٔ اپلیکیشن است** تا رسید را داخلِ صفحهٔ سفارش نمایش
دهد و دکمهٔ «دانلود PDF» را بسازد.

## جریانِ کار (سمتِ سرور — انجام‌شده)

1. تکنسین در اپِ خودش وضعیتِ سفارش را روی **«انتقال به تعمیرگاه»** می‌گذارد و
   (اختیاری) یک متنِ توضیح می‌نویسد.
2. سرور یک رسید با کدِ `TR-YYMM-NNNNN` و یک `token` ۴۸کاراکتریِ غیرقابل‌حدس
   می‌سازد. قالبِ رسمیِ رسید (با مهر و امضای مجموعه) از رویِ دادهٔ همان سفارش
   ساخته می‌شود — تکنسین امضا نمی‌کند.
3. لینکِ رسید با پیامک برای مشتری ارسال می‌شود. **این لینک به صفحهٔ همان سفارش
   در اپ می‌رود** (`https://app.tamironline.com/orders/{order_id}` — قابلِ تغییر
   با تنظیمِ `transfer_receipt_app_url_template`).

## نقشِ اپ

### ★ نمایش داخلِ جزئیاتِ سفارش (مهم — پیش‌فرض)

رسیدهای انتقالِ هر سفارش **مستقیماً در پاسخِ جزئیاتِ سفارش** می‌آیند تا مشتری
آن‌ها را در همان صفحهٔ سفارش ببیند:

```
GET /api/bff/v1/customer/orders/{id}
```

پاسخ، کلیدِ `data.transfer_receipts` (آرایه) دارد. اگر سفارش رسیدی نداشته باشد،
آرایه خالی است. هر عنصر:

```jsonc
{
  "data": {
    "id": 78904,
    "tracking_code": "ORD-2607-01330",
    // ... بقیهٔ فیلدهای سفارش ...
    "transfer_receipts": [
      {
        "code": "TR-2607-00042",                // کدِ رسید (نمایش به کاربر)
        "description": "برد سیم‌کشی جهت تعمیر به کارگاه منتقل شد.",  // ممکن است null باشد
        "created_at": "2026-07-13T08:31:00+00:00", // ISO-8601 UTC
        "print_url": "https://panel.tamironline.com/crm/transfer-receipt/NkmT5ao...9" // نمای HTMLِ رسمیِ رسید
      }
    ]
  }
}
```

### فیلدها

| فیلد          | نوع            | توضیح |
|---------------|----------------|-------|
| `code`        | string         | کدِ یکتای رسید — به کاربر نشان دهید. |
| `description` | string \| null | متنِ توضیحِ تکنسین. اگر `null` بود، بخش را نشان ندهید. |
| `created_at`  | string (ISO)   | زمانِ ثبت (UTC) — با تقویمِ شمسی نمایش دهید. |
| `print_url`   | string         | آدرسِ نمای رسمیِ HTMLِ رسید (با مهر و امضا، فونتِ وزیر). مبنایِ دکمهٔ «دانلود PDF». بدونِ لاگین باز می‌شود. |

### ★ دکمهٔ «دانلود PDF» (سمتِ اپ)

تولیدِ PDF **سمتِ فرانت** انجام می‌شود:

- سریع‌ترین راه: دکمه‌ای که `print_url` را باز می‌کند (WebView/مرورگر). صفحهٔ
  رسید دکمهٔ «چاپ» دارد که کاربر می‌تواند «ذخیره به‌صورت PDF» بگیرد.
- راهِ حرفه‌ای‌تر: `print_url` را در یک WebView بارگذاری کنید و با ابزارِ PWA/
  Native (مثلِ `react-to-print`، `html2pdf`، یا API چاپِ سیستم‌عامل) خروجیِ PDF
  بگیرید. صفحه واکنش‌گراست و برای A4 بهینه شده (`@media print`).

> نکته: `print_url` نمای رسمی (مهر و امضای مجموعه) است. نیازی به ساختِ قالبِ
> جداگانه در اپ نیست؛ همین صفحه را برای PDF استفاده کنید. اگر ترجیح می‌دهید
> قالب را خودتان بسازید، از `code` / `description` / `created_at` + دادهٔ سفارش
> (دستگاه، برند، آدرس، مشتری) که همگی در همان پاسخِ سفارش هستند استفاده کنید.

### پیامک

متنِ پیامکی که مشتری می‌گیرد شاملِ همین لینکِ سفارش است. با بازکردنِ لینک،
کاربر به صفحهٔ سفارش در اپ می‌رسد و رسید را در بخشِ بالا می‌بیند. برای پشتیبانی
از deep-link، مسیرِ `orders/{order_id}` را در اپ handle کنید.

## خلاصهٔ چک‌لیستِ اپ

- [ ] در صفحهٔ جزئیاتِ سفارش، اگر `transfer_receipts` خالی نبود، بخشِ «رسیدِ
      انتقال» را نشان بده (code + تاریخِ شمسی + description در صورتِ وجود).
- [ ] دکمهٔ «مشاهده/دانلود PDF» که `print_url` را باز می‌کند یا به PDF تبدیل می‌کند.
- [ ] deep-link مسیرِ `orders/{order_id}` را از پیامک handle کن.
